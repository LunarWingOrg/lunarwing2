# Agent Rules — lunardepth4lunarwing

## What This Is

Opt-in LunarWing external worker for the LunarDepth fork of DeepSeek Harness. The pinned source is `lunarwing/lunardepth` at `da06c33b2091546dc38c61b95452ce27a4ce32d5`. The lane implements `docs/proposals/LUNARDEPTH_WORKER_LANE.md`; treat that design and `docs/ops/WORKER-CONTAINERS.md` as the security contract.

The daemon dispatches `create_job(mode: "lunardepth")` to a non-root bridge. The bridge delegates over the `-ipc-v2` Unix socket to the non-root task runner, which alone connects to LunarDepth on `127.0.0.1:19091/ws/agent` with `lunarwing-agent-v1`. Never connect the daemon directly to the harness or put the hub credential in the task container.

## Key Files

- `config/lunarwing-lane.patch.yml` — final immutable overlay. Every security row restates its exact upstream package `name` and an explicit `disabled` value. The complete `permission` row allows only `workspace-write`/`ask`; `danger-full-access`, `auto`, `dsh-bash-local`, `runnerCommand`, and `runnerFailureSignatures` are forbidden.
- `scripts/lunarwing_bridge.ts` — authenticated hub WebSocket server. It advertises no optional capabilities and delegates one active task at a time.
- `scripts/lunardepth_task_runner.ts` — Unix-socket runner and loopback LunarDepth WebSocket client. Accept the daemon's empty environment map, `user_id`, and string metadata; reject non-empty environment/credential grants, cron, steering, resume, and tool-proxy frames rather than discarding them silently.
- `scripts/lunarwing_runtime.ts` — protocol types, validation, bounds, and constant-time bearer comparison. Keep it aligned with `agent_comm_protocol.json`.
- `scripts/workspace_path.ts` — realpath workspace mapping and overlap detection. `/workspace` is only the fallback; each task uses the realpath of `project_dir`.
- `entrypoint-task-setup.sh` — regenerates all lower configuration layers from root-owned templates on every start, preserving only named session-data directories. The profile template is generated by the pinned source's `initProfile` during the image build, never by a hand-written profile `package.json`.
- `scripts/effective_config_assert.ts` — pre-readiness composition, package-resolution, schema-version, and unchanged-manifest gate. `package.json` must be byte-identical before the dump, after the dump, and after real readiness.
- `scripts/sandbox_smoke.ts` — model-independent confined bash smoke. Require full built-in bwrap/Landlock enforcement, a successful workspace write and `mktemp`, and a denied escape.
- `entrypoint-split.sh` — task uid:gid `10005:10005`, bridge `10105:10005`. Preserve rootful workspace inode and rootless keep-id checks.

## Security Choices

- `tool-fs-search` is disabled because its unsandboxed ripgrep can read the harness model key through `/proc/<pid>/environ`. `ptc-runtime` and `workflow-ptc` are also disabled in v1.
- `TMPDIR`, `TMP`, and `TEMP` are all `/tmp`. The launcher's inherited values cannot be replaced by `.env`, and both built-in runners permit confined `mktemp` there.
- The launch cwd is the root-owned empty `/run/lunardepth-launch`. `HOME` is regenerated, `WS_NO_BUFFER_UTIL=1` and `WS_NO_UTF_8_VALIDATE=1` are mandatory, and `PATH` contains only absolute root-owned directories.
- `LUNARDEPTH_API_KEY` is task-visible, including to the model. Issue a separately revocable key per tenant, limited to that tenant's inference. It must never reach the bridge, overlay, argv, logs, examples, or health output.
- The worker never opens a tunnel, relay, pairing link, public share, non-loopback harness listener, telemetry exporter, DeepSeek account route, public fetch/search path, or self-update path. Only the bridge publishes WS `9090` and health `8443`, and only onto host loopback through mt-admin.

## Build Notes

Node is `22.23.4-bookworm-slim` at the same digest as `CI_NODE_IMAGE`; pnpm is exactly `11.7.0`. `DEBIAN_SNAPSHOT` moves with every other worker and `CI_DEBIAN_SNAPSHOT`. The Dockerfile and `.gitlab/scripts/build-worker-image.sh` must carry the same full source SHA and both ancestry markers. Branch names, short SHAs, moving tags, alternate repositories, and `latest` source pins fail closed.

The build runs the pinned toolchain guard before installation, uses `pnpm install --frozen-lockfile`, runs focused worker tests/typechecks, and deploys `dsh-python-runtime-closure` through `build-exe-for-python-sdk.ts --deploy-to`. Resolve both `@lunardepth/dsh-lunarwing-worker-app` and `@lunardepth/dsh-lunarwing-worker` from that materialized closure. The runtime invokes the built launcher, never `tsx` or a source checkout.

The lane replaces the pinned script's legacy deploy block with pnpm's shared-lockfile deploy: frozen, injected workspace packages, and `minimumReleaseAgeStrict=true`. The exact-block transformation must fail on source drift. `pnpm-workspace.yaml` must stay byte-identical, including `minimumReleaseAgeExclude`; `verify_deployed_closure.ts` rejects every installed external `name@version` absent from the source lockfile and records the sorted inventory hash in `worker-inputs.sha256`. `harden_image_modes.sh` clears inherited write/set-ID bits with five-digit modes before the final closure assertion.

`ARG SOURCE_DATE_EPOCH=0` precedes account creation and its shadow-day assertion. Remove source metadata, caches, development dependencies, smoke state, and writable application/template files. Candidate and uncached clean-rebuild whole-image digests must match; the protected candidate, out-of-band verification, CRITICAL scan, and manual promotion are mandatory.

## Testing

Run the lane's Node tests, Python policy tests, shell syntax checks, `.gitlab` worker fixtures, and `ic/scripts/check-mt-admin.sh` after changes. The image build must run the real entrypoint with `--network=none`; live acceptance additionally uses `mt-admin worker-listeners`, `worker-egress`, and `worker-smoke` on a disposable tenant. Do not claim live TensorMoon inference, OpenRC execution, or a green exact-head MR pipeline without that evidence.
