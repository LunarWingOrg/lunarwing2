## Verification contract

Item 16 repeats item 15's upgrade-preservation check on a systemd host. This test
checks the persisted workspace document consumed by
`Workspace::system_prompt_for_context`, rather than merely comparing repository
seed/template files. Current source imports and seeds only missing workspace
files, so an existing customized prompt document must remain unchanged
(`ic/src/app.rs:1148-1197`, `ic/src/workspace/mod.rs:2013-2091`).

All tenant lifecycle and status operations used
`ic/scripts/lunarwing-mt-admin.sh`. Direct unit checks used the tenant's
`systemctl --user` manager with its own `XDG_RUNTIME_DIR`, never the system bus.

## Real systemd upgrade

The actual upgrade command ran in tmux:

```text
upgrade-tenant aj16sys \
  --target aj/kimi-16-20260825-1800 \
  --source-repo /tmp/lunarwing-item16-source.git \
  --no-backup
```

The source mirror lived under `/tmp` so the unprivileged tenant Git process could
traverse it. The upgrade fetched as `aj16sys`, stopped the tenant, checked out
exact target commit `479a9c051ebaeb0ce2448f9d027dc80998b97e35`, release-built
LunarWing and the XMPP bridge, rebuilt and installed all 13 WASM extensions,
re-rendered the systemd user units, preserved existing env values while patching,
and restarted the tenant successfully. The final checkout matched the target
commit exactly.

After the upgrade, the authenticated API returned the same `AGENTS.md` bytes,
SHA-256, and `updated_at` value. A separate `restart-tenant aj16sys` produced the
same result again. Both times the expected six systemd user units were active;
after the separate restart, `mt-admin status` again reported PostgreSQL running
and LunarVision healthy.

This verifies that neither checkout/rebuild nor startup seeding overwrites an
existing customized system-prompt workspace document on systemd.
