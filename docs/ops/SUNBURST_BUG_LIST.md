# Sunburst Bug List — Audited Status

- **Original sources:** Sunburst instance (`cmc`, LunarWing 2.0.2.0–2.0.3.0), seven testing tenants, cmc's bug tracker, and the Dwarfstar testing tenant.
- **Repository audit:** 2026-08-02 at `1e319bf2fe4a`.
- **Method:** current source, regression tests, related incident documents, and Git history were checked for every entry. No live Sunburst/Dwarfstar tenant was available, so deployment-only findings are explicitly marked for live revalidation.

## Status legend

- ✅ **Fixed** — the current source contains the repair and direct regression coverage or a focused fix commit.
- 🟡 **Open / partial** — the current source still contains the defect or does not close the reported deployment gap.
- ❓ **Live revalidation required** — repository inspection cannot establish the current tenant state.
- ⚪ **Not a product bug / misclassified** — expected setup behavior, a duplicate, or an incorrectly attributed report.
- 📘 **Documented behavior** — known operator behavior remains documented; an ergonomic improvement may still be possible.

| BUG-001 | Skill File Duplication on Restart (Gap #2) | ✅ **Fixed in current source; historical field count not reproduced.** Startup migration loads persisted shared skill docs, extracts `V2SkillMetadata.content_hash`, and skips unchanged content (`ic/src/bridge/skill_migration.rs:51-98`). Re-enable SIS only with a live cleanup/restart check because the historical 132-file cause was never captured in a reproducer. |
| BUG-002 | Thread JSON Indexing Leak (Gap #1) | ✅ **Fixed.** Commit `406cffa` excludes normalized `engine/.runtime/**` paths from chunk generation, adds a migration that removes legacy chunks, and adds the `runtime_documents_persist_without_entering_search` regression (`ic/src/workspace/document.rs:59-73`, `ic/src/workspace/mod.rs:1732-1745`, `:2274-2332`, `ic/migrations/V23__exclude_engine_runtime_from_search.sql`). |

| BUG-014 | Trigger Payloads Not Propagating to Mission Thread State | ✅ **Fixed.** Commit `e10c131` seeds `trigger_payload` into durable initial orchestrator state, preserves it across gate pause/resume, and broadcasts terminal events after persistence. `fire_with_trigger_payload` exercises an actual mission REPL read (`ic/crates/lunarwing_engine/src/runtime/mission.rs:460-570`, `:3415-3463`; see `docs/ops/SIS_FIX_PROPOSAL.md`). |

A live restart is still useful to confirm old tenant lease files are reconciled. |

| BUG-021 | `ssh_git` Null Ref Parameter Handling (Dwarfstar BUG-001) | ✅ **Fixed.** Commit `c8b277d` treats JSON null, empty/whitespace, and case-insensitive literal `"null"` as an omitted ref. Regression tests cover null-like and real refs (`ic/src/tools/builtin/ssh_git.rs:68-74`, `:640-661`; `docs/bugs/BUG-ssh-git-null-ref-serialization.md`). |
| BUG-022 | Job Stuck Pending Forever — Ghost Job (Dwarfstar BUG-002) | ✅ **Fixed.** Commit `6f07168` makes `list_jobs`, `job_status`, and `job_events` query persisted sandbox jobs when in-memory context is absent, with owner checks and a restart regression (`ic/src/tools/builtin/job.rs:86-133`, `:1585-1636`, `:1760-1818`, `:2583-2665`). | BUG-023 | External Worker Job Marked Failed Despite Success (Dwarfstar BUG-003) | ✅ **Fixed in source; live worker revalidation recommended.** Commit `a2e9c48` sizes the host/tool monitor timeout from the worker timeout plus grace instead of using a shorter fixed ceiling. The job is marked `running` with `started_at` before dispatch (`ic/src/tools/builtin/job.rs:908-938`), and commit `7e9dc48` gives timeout/cancel terminal states explicit DB/SSE handling. Integration coverage verifies timeout cancellation and async terminalization (`ic/tests/external_worker_integration.rs:664-751`). A task that finishes side effects but never reports a result before its configured deadline is still correctly classified as timed out. |

| BUG-004 | Multica Registration — `PathNotAllowed` | ✅ **Fixed.** `EndpointPattern` now supports a wildcard `path_prefix` form: a leading `*` (e.g. `*/api/`) matches the remainder anywhere in the normalized path at a segment boundary, so servers deployed under an arbitrary base path stay within their declared API subtree (`ic/src/tools/wasm/capabilities.rs`, used by both tool and channel HTTP gates via `ic/src/tools/wasm/allowlist.rs`). Both Multica manifests adopt `*/api/` (`ic/channels-src/multica/multica.capabilities.json:39`, `ic/tools-src/multica-bridge/multica-bridge.capabilities.json:128`), so `/cotter-openclaw/api/daemon/register` now passes while non-API paths and traversal collapses stay denied. Registry patch bumps per CI source-version policy: channel 0.1.4→0.1.5, tool 0.1.0→0.1.1. Deployed tenants pick up the fix on channel/tool reinstall or upgrade; live revalidation on Sunburst recommended. |
| BUG-005 | “Multica Daemon” Connection Refused at `127.0.0.1:6680/poll` | ⚪ **Misclassified duplicate of BUG-006, not Multica.** No Multica source uses port 6680 or `/poll`; those belong to the DarkIRC adapter (`ic/channels-src/darkirc/src/lib.rs:10`, `:307-311`, `ic/channels-src/darkirc/adapter/darkirc_adapter.py:50`). | BUG-007 | WeeChat Relay 401 Unauthorized | ❓ **Live tenant drift remains unverified; do not mark fixed.** Current source bootstraps one `RELAY_PASSWORD`, writes a dedicated `weechat.env`, injects the same value into the WASM config, and validates new relay configs (`ic/scripts/lunarwing-mt-admin.sh:2779-2957`, `ic/src/channels/wasm/setup.rs:481-530`, `:709-730`). | BUG-010 | Tool Parameter Discovery Gap (“Bug B”) | ✅ **Fixed.** `tool_info` supports compact names, curated summary, and complete discovery schema; WASM wrappers separately expose their full discovery schema (`ic/src/tools/builtin/tool_info.rs:1-177`, `ic/src/tools/wasm/wrapper.rs:1385-1412`). Services and supported mt-admin container operations set their environment explicitly, but no tenant pairing-wrapper command currently auto-injects the base directory. |

## Feature gaps

| Feature | Audited status |
|---|---|
| FEAT-001 — MCP server layer has no stdio support | ✅ **Implemented.** MCP supports HTTP, managed stdio subprocesses, and Unix sockets through `McpTransport`; typed stdio config, factory dispatch, process lifecycle, and tests are present (`ic/src/tools/mcp/config.rs:32-52`, `ic/src/tools/mcp/factory.rs`, `ic/src/tools/mcp/stdio_transport.rs`; see `docs/ops/MCP_ADDITIONS.md`). |
| FEAT-002 — MCP auth defaults to OAuth / no API-key header support | 🟡 **Partially resolved.** Arbitrary HTTP headers, including `Authorization` and `X-Api-Key`, are supported and a custom authorization header suppresses OAuth injection (`ic/src/tools/mcp/config.rs:67-73`, `:306-387`, `ic/src/tools/mcp/http_transport.rs:84-108`). However, HTTP header values are still stored directly in MCP config; owner-scoped secret-name references currently exist only for stdio environment variables. Secret-backed HTTP header injection remains a real gap. |
