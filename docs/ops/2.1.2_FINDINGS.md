# Findings from the earlier source audit

Goal 38 on `212g38` addresses findings 1–4 below. The remaining findings
are separate follow-ups; line numbers in the original audit refer to its
then-current HEAD.
1. **ITEM9-F1 [HIGH] retry_attempt leak into trigger payload** — `refire_mission_thread` (runtime/mission.rs:2278-2285): inserts `RETRY_ATTEMPT_METADATA_KEY` into the payload map → flows into prompts + persisted `last_trigger_payload`, violating the constant's own doc invariant. Duplicate of `persist_retry_attempt_marker` (:2246) which already does this correctly via metadata. ~8 lines, delete-the-injection fix. **Release gate.**
2. **ITEM9-F2 [HIGH] dedup key released on GatePaused** — `process_mission_outcome_and_notify` (mission.rs:~2933-2949): the release fires for `!Completed` — includes `GatePaused` and `Stopped`. A redelivered trigger while a fire sits approval-paused double-fires (WI#69 regression class). Fix = exclude GatePaused (and Stopped?) from the release, or scope to retry-scheduled outcomes only. **Release gate.**
3. **ITEM9-F3 [MED] restart sweep iterates in-memory active set** — `recover_pending_mission_retries` (mission.rs:2338-2358) iterates `self.active.read().await` — missions whose retries were scheduled in a PREVIOUS daemon life are missed if they're not in the current active set. Persisted markers exist but the sweep doesn't scan the store. (This is mine, cross-confirmed; rides with F1/F2 or 2.1.3.)
4. **F10 [MED] MissionUpdate.retry_policy exists but mission_update tool schema/params never surface it** — struct has `retry_policy: Option<MissionRetryPolicy>` (mission.rs:211) but the tool-facing extraction (effect_adapter.rs mission_update handler) doesn't expose retry params; ENGINE-V2.md claims them. **At audit time: open — doc/contract drift + missing surface.**

## Goal 38 remediation (2026-09-23)

- **ITEM9-F1:** Retry attempts stay in the spawned thread's top-level metadata
  (`persist_retry_attempt_marker`); `refire_mission_thread` forwards the trigger
  payload unchanged. Neither the model's trigger context nor
  `Mission::last_trigger_payload` receives `retry_attempt`.
- **ITEM9-F2:** Dedup keys are released on terminal non-completions (`Failed`,
  `Stopped`, `MaxIterations`) only. `GatePaused` retains ownership while the
  original thread awaits approval, so redelivery cannot spawn a second fire.
- **ITEM9-F3:** Startup retry recovery enumerates persisted missions across
  projects via `Store::list_all_missions_global` instead of relying on the
  manager's in-memory active index. Paused/terminal missions remain excluded.
  Project-listing failures propagate rather than silently skipping pending
  retries; the startup caller logs the failure.
- **F10:** `mission_update` advertises the four retry-policy scalars already
  parsed by the effect adapter (`max_retries`, `initial_delay_secs`,
  `backoff_multiplier`, `max_delay_secs`); the stale "up to 2 scalars" comment
  and duplicate parser documentation were removed.

Targeted engine tests cover unchanged retry payloads, paused-gate dedup,
and recovery without an active-index entry; bridge tests cover tool parameter
mapping. The operator should still verify the restart behavior on a live
tenant after deployment.
6. **escape_content backslash + severity-gated escaping [MED, mitigated]** — sanitizer.rs no longer exists as a file at HEAD; escape logic moved into `lunarwing_safety` with unconditional `neutralize_role_token_openers` at all sinks (rig_adapter.rs:208/213, provider.rs, +9 call sites). The two residual hardening ideas (backslash-form escaping, non-critical-severity coverage) live on as **defense-in-depth candidates, LOW**
