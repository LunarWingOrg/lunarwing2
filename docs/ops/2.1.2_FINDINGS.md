## Goal 38 remediation (2026-09-23)

- **ITEM9-F1:** Retry attempts stay in the spawned thread's top-level metadata
  (`persist_retry_attempt_marker`); `refire_mission_thread` forwards the trigger
  payload unchanged. Neither the model's trigger context nor
  `Mission::last_trigger_payload` receives `retry_attempt`.
- **ITEM9-F2:** Dedup keys are released on terminal non-completions (`Failed`,
  `Stopped`, `MaxIterations`) only. `GatePaused` retains ownership while the
  original thread awaits approval, so redelivery cannot spawn a second fire.
- **ITEM9-F3:** Startup retry recovery enumerates persisted missions across
  projects via `Store::list_all_missions_global` instead of relying on the
  manager's in-memory active index. Paused/terminal missions remain excluded.
  Project-listing failures propagate rather than silently skipping pending
  retries; the startup caller logs the failure.
- **F10:** `mission_update` advertises the four retry-policy scalars already
  parsed by the effect adapter (`max_retries`, `initial_delay_secs`,
  `backoff_multiplier`, `max_delay_secs`); the stale "up to 2 scalars" comment
  and duplicate parser documentation were removed.

Targeted engine tests cover unchanged retry payloads, paused-gate dedup,
and recovery without an active-index entry; bridge tests cover tool parameter
mapping. The operator should still verify the restart behavior on a live
tenant after deployment.
6. **escape_content backslash + severity-gated escaping [MED, mitigated]** — the legacy sanitizer now lives at `ic/crates/lunarwing_safety/src/sanitizer.rs`. At audit time its critical-only escape inserted a backslash before `<|`, leaving the special-token opener intact. Other sinks already used unconditional `neutralize_role_token_openers` (for example `rig_adapter.rs` and `provider.rs`). **Goal 39 closes the remaining sanitizer/tool-output gap; see below.**

## Earlier `212g39` sanitizer remediation (2026-09-23)

`Sanitizer::sanitize` now inserts a zero-width space after `<` in every `<|`
opener, independently of scanner severity, instead of prepending a backslash
only in its critical-only escape. The other critical-only transformations
(null-byte removal, line-start role-label and `[INST]` escaping) remain
unchanged. `SafetyLayer::sanitize_tool_output` also applies the same
neutralizer when injection scanning is disabled; `was_modified` accurately
reflects either transformation. This is defense in depth on top of the
existing prompt sinks, which still neutralize role-token openers. Token
openers in returned tool text now carry U+200B, which can affect byte-for-byte
consumers of that sanitized output; the raw tool response is unchanged.
Regression tests cover both injection-scan settings and already backslashed
role delimiters.

## Goal 40 remediation (2026-09-23)

The stale SSH-agent socket finding is fixed with sweetiebot's preferred shape:
workers bind-mount the socket's parent **directory**, not the socket file, so
the fresh socket inode a daemon restart binds at the same path is resolved at
connect time — a daemon-only restart (upgrade, crash, `systemctl restart
lunarwing`) no longer bricks git auth in every mounted worker.

The daemon socket moved from `<tenant>/lunarwing/run/ssh-agent.sock` to a
dedicated `<tenant>/lunarwing/run/ssh-agent/ssh-agent.sock` subdir. The subdir
(rather than mounting all of `run/`) preserves the WI#205 boundary: `run/`
also holds the daemon's REPL control socket `lunarwing.sock` and other
protected runtime state, which must stay unreachable from untrusted worker
containers; the mount now exposes only the agent.

- `SshAgentServer::start` creates the parent directory and chmods it `0o755`
  (the daemon unit runs `UMask=0077`; a daemon-created `0700` dir would block
  worker UIDs from traversing to the `0o666` socket). Regression test covers
  directory creation, mode, and socket cleanup.
- mt-admin mounts `$(tenant_run_dir)/ssh-agent` at `/tmp/ssh-agent` with
  `SSH_AUTH_SOCK=/tmp/ssh-agent/ssh-agent.sock` on every non-kimi lane —
  Quadlet renderer (`07-units-systemd.sh`) and the imperative
  opencode/opencode2/pebble launches (`09-worker-config.sh`). The kimi lane
  still mounts nothing (WI#206).
- Launch contracts gained an `ssh-agent-dir` marker (`OPENCODE_`/`OPENCODE2_`
  bumped; new `PEBBLE_ROOTLESS_LAUNCH_CONTRACT`), so existing containers still
  carrying the legacy file mount force-recreate on their next start.
- `start-tenant` pre-creates the `0755` directory instead of the legacy
  touch-file (a regular file at the socket path would now block the daemon's
  bind), and the daemon-before-workers ordering comments are updated — the
  post-key-upload daemon bounce no longer has to precede worker creation for
  socket-inode correctness.

Harness assertions pin the directory mount (quadlet + all three imperative
lanes) and the contract bumps. Existing tenants pick the fix up via any
re-render (start-tenant / restart-worker) — no manual migration. Operator
verification on a live tenant (daemon restart + worker `ssh-add -l`) remains.

## Agent goal 39 / WI#226 remediation (2026-09-23)

The directory mount introduced by goal 40 is now **read-only** (`:ro,z`) in
Quadlet and all three imperative worker launch paths (opencode, opencode2,
pebble). This blocks a worker from unlinking/rebinding the shared host SSH
agent socket while retaining `:z` shared SELinux relabeling and the fresh-inode
behavior on daemon restart. The socket itself remains mode `0o666` for
`connect(2)`. Kimi still has no socket mount.

The rendered Quadlet file hash changes, and the imperative launch contracts
now carry `ssh-agent-dir-ro`. The latter applies to rootful/OpenRC launches as
well as rootless Podman so old RW-mount containers force-recreate at the next
worker start; no daemon restart is needed just to change the mount policy.
The mt-admin harness covers each rendered mount, all three imperative mount
arguments, and legacy rootless/rootful hash migration. Live worker SSH after
recreation remains an operator acceptance check.
