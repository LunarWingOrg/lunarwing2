# WI#232 + WI#231 — Health/Self-Heal Pipeline Lifecycle Fixes (Goal 8, v2.1.2.0)

Verification record for [WI#232](https://git.lunarwing.org/lunarwing/lunarwing2/-/work_items/232) (upgrade path never refreshes the deployed health/self-heal pipeline) and [WI#231](https://git.lunarwing.org/lunarwing/lunarwing2/-/work_items/231) (self-heal restarts deliberately-stopped tenants' units).

Both items describe sibling manifestations of one class of failure: the host-global pipeline's lifecycle was never coordinated with the tenant/upgrade lifecycle, and the resulting defects masqueraded as podman store corruption (WI#225's "wiper" was stale pipeline code blindly restarting deliberately-stopped tenants' units mid-operation).

---

## WI#232 — refresh-on-upgrade (G1) + drift detection (G2)

The tracker's pick was **G3** (both candidates). Both are implemented.

### G1 — `upgrade-tenant` refreshes the pipeline

`upgrade_tenant_locked` (`ic/scripts/mt-admin-lib/04-tenant-lifecycle.sh`) now calls `ensure_health_pipeline` after `start_tenant`, under the same enable conditions as `add-tenant` (`DEFAULT_HEALTH_ENABLED=true`, no `--no-health` opt-out), and only when a pipeline is actually deployed (`$HEALTH_LIB_DIR/cron-wrapper.sh` or the launcher exists) — `add-tenant` remains the installer for hosts that never had one; an upgrade never silently installs a host-wide remediation schedule.

`ensure_health_pipeline` is idempotent and preserves an existing `/etc/lunarwing/health.env` (operator Gotify creds survive — acceptance criterion 2), so the refresh is safe to run on every upgrade. A side effect: because `upgrade_tenant_locked` stops the tenant mid-upgrade and the new F2 stop-path (below) disables its units, a health tick landing in the stop→checkout→build→start window can no longer resurrect half-upgraded units.

### G2 — version stamp + visible drift

- `ensure_health_pipeline` stamps the deployed copy with a content hash of the pipeline scripts it synced (`health_pipeline_stamp_tree` → `$HEALTH_LIB_DIR/.pipeline-version`), and reconciles `HEALTH_PIPELINE_EXPECTED_VERSION` into `/etc/lunarwing/health.env` using the same targeted one-line rewrite as the existing `LUNARWING_SERVICE_MANAGER`/`SELF_HEAL_TENANTS_FILE` reconciles (operator edits preserved).
- New `health-pipeline.sh` check component (wired into `infrastructure-health-check.sh` as `pipeline`) hashes the deployed scripts it runs alongside and compares:
  - live == expected → `healthy`
  - stamp file absent (a pre-WI#232 deploy — the live ajhermes condition of Aug-31 `health-systemd.sh` vs current tree) → `degraded` with a visible issue
  - expected version unrecorded → `degraded`
  - deploy hand-edited after install (stamp != live) → `degraded`
  - live != expected (deploy skipped the refresh) → `degraded`, naming `upgrade-tenant` as the remedy
- The component is registered `NO_REMEDY` + `MONITOR_ONLY` in self-heal, so drift escalates as a page but can never trigger a restart.

Hash computation detail that mattered in testing: `sha256sum` echoes its argument, so each file is hashed from *inside* its directory (bare basenames in the digest stream); otherwise the source-tree stamp and the deployed-copy live hash would differ for identical content.

### Acceptance status (WI#232)

1. Refresh-on-upgrade: implemented (G1); byte-freshness is delivered by the same `cp -a` the installer uses.
2. `health.env` preserved: yes (existing write-if-absent + targeted-line reconcile paths untouched).
3. G2 drift signal: implemented; a manually-aged/hand-edited deploy degrades the next report with a version-mismatch issue (verified in the sandbox below; visible in the report JSON and therefore the journal).
4. Regression tests: `test-health-pipeline.sh` (new suite, 8 cases) in `ic-infrastructure-health-check/tests/`.
5. OpenRC parity: the refresh path is the same init-agnostic `ensure_health_pipeline`; the check is a plain content hash with no init dependency.

## WI#231 — remediation gate (F1) + stop-tenant disables units (F2)

The tracker's pick was **F1 as the core fix, F2 as belt-and-suspenders**. Both are implemented.

### F1 — lifecycle gate in self-heal

`remediate_component` (`ic-infrastructure-health-check/lunarwing-self-heal.sh`) now consults tenant lifecycle before remediating a **tenant-scoped** unit (`remediation_allowed`):

- Remediation requires the tenant's primary daemon (`lunarwing-<t>`) to be observed active, **or** the unit itself to be in a fault state — systemd `SubState` `failed`/`auto-restart`, `ActiveState=failed` (a SIGKILLed daemon), or OpenRC `rc-service status` reporting `crashed` (Addendum 6's equivalent rc-service state check). A crash is a crash even on a stopped tenant; never-mask is preserved.
- A cleanly-stopped tenant's inactive units skip the *entire* remediation path — flap/max-retries escalation included — so state no longer accumulates retries for stopped tenants (the `lunarwing-vision-antelope retries: 3` re-judging at every 15-min tick). The unhealthy observation itself is still recorded pre-gate, so a later `start-tenant` sees a fresh grace streak.
- **Fail-open contract**: any inconclusive probe — unresolvable tenant user, wedged bus (ActiveState read != `inactive`), registry gap, unknown manager — allows remediation. The gate must never become a new way to mask a real outage. Only a *positive* observation of the primary being inactive closes it.
- Init-agnostic: systemd probes `ActiveState` on the tenant user bus; OpenRC classifies the primary from one bounded `rc-service status` (`started`/`crashed`/`stopped`/`unknown` — the same keywords mt-admin's `openrc_service_state` parses).

### F2 — stop-tenant disables units

- systemd `stop_tenant_systemd` disables the enable-list units after stopping them (Quadlet-generated units excluded: `disable` fails on generated units and F3-B already grades them `skipped`). `start_tenant_systemd`'s existing `enable` re-enables on the way up.
- OpenRC `stop_tenant_openrc` removes runlevel persistence for all of the tenant's services after stopping them (new `openrc_service_in_any_runlevel` guard keeps never-started tenants churn-free). `start_tenant_openrc`'s existing boot-enable pass re-adds everything.
- Effect: health-systemd F3-B's lazy probe grades a stopped tenant's units `skipped`, and health-openrc's `tenant_started()` (keyed on the primary's runlevel presence) flips the whole stopped tenant to `skipped` — the classifier support the WI described as already existing is now actually reachable by stop-tenant.

### Acceptance status (WI#231)

1. Stopped tenant, 5 consecutive ticks: no restart attempts, restart counter untouched — matrix P1/P2.
2. No retry/escalation accumulation for stopped tenants — matrix P2 (state assertions across 5 runs).
3. Genuinely failed unit of a started tenant still remediated in one tick — matrix P3/P6 (never-mask preserved; chaos CH10/CH11/CH16/CH17 re-verified).
4. OpenRC gate parity — matrix P5/P6/P4c (`_openrc_primary_class`, `crashed` bypass).
5. Regression tests in `ic-infrastructure-health-check/tests/` — matrix Section P (P1–P8, 22 assertions) plus mt-admin harness cases for the F2 stop/start parity.

Live multi-tick confirmation on a real tenant host (4+ ticks with `journalctl` evidence, antelope's `retries: 3` clearing) remains an operator step — this session cannot provision tenants.

## Rollback / compatibility notes

- The upgrade-path refresh only fires when a pipeline is already deployed; it cannot install a schedule the operator never enabled.
- `stop-tenant`'s disable is reversible by the existing `start-tenant` paths; a disable failure is a WARNING and never fails the stop.
- Self-heal's gate is strictly additive: units that were remediated before are still remediated unless their tenant's primary is observed inactive — the fail-open contract means a broken probe degrades to the old behavior rather than masking outages.
- Pre-WI#232 deployed pipelines will report `degraded` (missing stamp) until the next `upgrade-tenant`/`enable-health-fleet.sh` run refreshes and stamps them — that is the intended loud signal, not a false alarm; `HEALTH_PIPELINE_CHECK_ENABLED=false` disables it for operators who want the old silence.
