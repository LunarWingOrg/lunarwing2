## Conclusion — what the !1254 review required and what this audit does

The !1254 review rejected the previous attempt with one P1: the pebble
security fix updated **`pebble/Cargo.lock` (a local mirror)** while
`pebble4lunarwing/Dockerfile` fetches a separate immutable upstream checkout
at `PEBBLE_REF=2d0f3786…` whose own `Cargo.lock` ships **rustls 0.23.41** —
so the published worker image would still compile the RUSTSEC-2026-0285
affected TLS stack, and "scanned the 26 local lockfile roots" did not
establish the audit's claim. This cycle fixes exactly that:

- The image was **actually rebuilt** on this dev VM (`podman build -f

  inside the build (`override: rustls 0.23.41 -> 0.23.45`,
  `override: rustls-webpki 0.103.13 -> 0.103.15` in the build log), the build

- The **actual pinned worker graph** (`pebble4lunarwing/upstream/Cargo.lock`

  advisory ignore list: `advisories ok`. Control: scanning the *unpatched*
  upstream lock instead trips `RUSTSEC-2026-0285` — the scan is demonstrably

  an appended unrelated `[[package]]` record, a dependency-only edit inside an

## Fixed this cycle — RUSTSEC-2026-0285

**rustls accepted TLS 1.3 handshake messages sent at the wrong encryption
level when they followed a key-changing message in the same record**,
violating RFC 8446 §5.1; a peer could send messages that should be encrypted
in plaintext without rustls rejecting the connection. Functionally the same
bug as Go's GO-2026-4340 (CVE-2025-61730).

- Advisory: <https://rustsec.org/advisories/RUSTSEC-2026-0285>
  (GHSA-2mjx-qc3c-rqvc); patched in `rustls >= 0.23.45`.
- Reached via `reqwest → hyper-rustls → rustls` in the pebble worker image,
  the pebble mirror tree, and ocr-sidecar. The `ic` main workspace was
  already on 0.23.45.
- **Worker image:** because upstream Pebble at the pinned commit has no newer
  release, the fix is the reviewed patched-lock build input described above —
  the image now compiles rustls 0.23.45 without giving up
  `--locked`/reproducibility: the input is digest-pinned, and the lock delta
  versus the fetched upstream checkout is re-verified inside the build.
