## Implemented contracts

### G8-F1 — instruction authority

- Both prompt builders require the self-modification policy explicitly. The
  execution loop supplies the same host-selected policy to prompt-overlay and
  runtime-orchestrator loading. A persisted overlay does not become new system
  instructions when `ORCHESTRATOR_SELF_MODIFY` is off.
- Generic memory writes no longer treat `metadata.source == "compiled_in"` or
  the `orchestrator:failures` title as proof of internal origin. Native compiled
  seeding and failure bookkeeping call `Store::save_internal_memory_doc`;
  `__save_memory_doc__` cannot select that entry point.
- The host writer and production store reject control-doc writes while the gate
  is off. Reserved `prompt:` / `orchestrator:` title prefixes and control tags
  are protected independently, including renamed tagged docs.
- The mission manager assigns insight workers a typed `MissionContext`, inherited
  by their children. Their host writer refuses shared and maintenance outputs
  even when self-modification is enabled. An opted-in maintenance mission can
  still save a runtime patch.

### G8-F3 — purpose-specific automatic recall

- Insight meta-prompts and first-step host retrieval use the conversational
  maintenance exclusion and positive whole-token relevance policy.
- The recall query comes from the current trigger's goal/message samples, never
  the generic extraction program or generated next focus. An absent/empty batch
  has no fallback recall. `__retrieve_docs__` arguments and mutable REPL state
  cannot replace the host-owned query or enable maintenance recall.
- Relevant prior knowledge retains source IDs and fixed untrusted labels.
  Explicit tools such as `memory_search` remain separate from automatic recall.

### G8-F5 — generated-history feedback

- Insight prompts exclude both `current_focus` and `approach_history`, including
  legacy values. Their output instructions request supporting evidence instead
  of a next agenda, and outcome processing does not adopt a new generated focus.
- Run reports remain in mission history for operational inspection. A no-save
  run therefore leaves an audit record without feeding its claims into the next
  extraction prompt.
- The extraction prompt now describes the current sampler accurately: project/
  user counts, potentially generated goals, and truncated User-role prefixes
  are not automatically authenticated human statements. Full G8-F2 input-source
  and G8-F4 evidence-validation work remains open.

### G8-F9 — honest durable saves

- `HybridStore` propagates serialization/workspace content-write errors before
  publishing a MemoryDoc or its path in the in-process cache.
- A failed rename write preserves the existing durable document, cache value,
  and source path. The old file is deleted only after the new write succeeds.
- A store-local write lock serializes document persistence/cache publication.
  Workspace-less stores retain their intentional in-memory semantics.
- This path uses the existing `Workspace::write` content/chunk contract. It does
  not alter the distinct append-committed/index-repair contract.

## Compatibility and remaining work

- No database migration or dependency update is required. The new thread-context
  field has a serde default for old thread records. The internal Store method
  has a default implementation for other Store adapters; adapters with a
  protected-write policy must explicitly support the native entry point.
- These controls govern newly assembled prompts and newly configured insight
  runs. Existing transcripts/checkpoints can already contain old system text or
  retrieved material; upgrading does not scrub them. Use fresh runs for the
  controlled incident experiment. Old suspended insight threads predate the new
  purpose field and should be drained before comparing behaviors.
- Restoring an older binary restores the metadata-based write exception and
  ungated overlay loader. Preserve the hardening when backporting; keep operator
  pauses and incident evidence intact during any rollback.
- **Still open:** G8-F2 eligible source turns and provenance; G8-F4 host-validated
  evidence, stable insight identity, and contradiction/upsert behavior; G8-F6
  project-scoped dispatch; G8-F7 restart-safe batch identity; G8-F8 explicit
  opt-out/purge/recreation semantics. Stale-file cleanup after a successful
  rename remains best-effort, as before; the G8-F9 regression targets failed
  content writes.
- The September 16 response still requires its original tenant/build/provider,
  thread/time, trace, and persistence evidence for causal attribution.
