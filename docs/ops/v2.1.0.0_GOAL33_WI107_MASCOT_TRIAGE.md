## Hypothesis verdicts

- **H1 (final-response emission gap) — partially confirmed, residual documented, not code-changed here.**
  Normal and streamed turns always end in `ChannelManager::respond` → final `response` event with emotes (H1 disproven for the happy path). Legacy-loop interrupt resolves to `respond("Interrupted.")` (`agent_loop.rs:2187`) → terminal `response` event fires.
  **Residual gap:** on the Engine V2 path an interrupt yields `ThreadOutcome::Stopped`, mapped to the empty-string sentinel in `thread_outcome_response` (`bridge/router.rs:103-114`) — deliberately suppressed by the outbound handler, so **no** terminal `response` event is emitted on engine-interrupt turns. Effect on the mascot: it lingers in `working` until the 30 s idle fallback; the UI's own `'status': Done` handler is the safety net for the chat bubble. The sentinel is a deliberate `!767` design decision (no assistant row in v1 history), so parity with the legacy `"Interrupted."` emission is a tracker-level decision, not something to flip inside a mascot fix. Flagged for WI#107 follow-up.
- **H2 (parsing gaps vs herd dialect) — CONFIRMED and FIXED.**
  The shipped keyword table had essentially no equine dialect (`nicker`, `whinny`, `snort`, tail flicks, pawing the ground, pinned ears) and was missing the most common live roleplay verbs (`smile`, `grin`, `giggle`, `laugh`, `nod`, `sigh`). Every such phrase produced zero emotes, leaving the mascot inert — the dominant live-cause.
  Fix: extended `KEYWORDS` in `ic/src/channels/web/emote.rs` (~50 additions), keeping the existing ordering contract (specific before broad; emote list order is the priority order):
  - Greet ← nicker/whinny/neigh/brohoof/hoof bump + smile/grin/beam (acknowledgment warmth ≈ wave sprite)
  - Love ← boop/headbutt/purr
  - Jump ← chortle/giggle/laugh/wrr/paws the ground/tosses mane/rears up/flutter
  - Rage ← pinned/flattened ears, pout
  - Alert ← perks/pricks her-his-their ears, ear flick, snort, nods
  - Sleep ← sigh (deflating → sleep sprite is closest)
  - Walk ← tail flick/swish/wag family, weight shifts, scamper
  Substring collisions reviewed (`flickers` vs tail keys avoided by multi-word keys; `nod`→`nods` avoids `node`; `neigh`/`beam`/`sigh` collision risk accepted as action-span-only). New regression tests: `parses_herd_dialect_phrases`, `herd_message_emotes_flow_end_to_end`.
- **H3 (markdown-emphasis false positives) — by design, documented, unchanged.**
  The parser contract is "single-asterisk italic span = roleplay action". Prose emphasis containing a keyword (e.g. `*important notice*` → `alert`) can classify; that is the documented presentation-layer trade-off in the module docs, and the WI's verification plan only asks for regression tests around known false-positive phrases — the existing two-layer guard (single-line, ≤120 chars, no nesting) plus keyword-driven vocabulary keeps the noise low enough. Not changed; the broader H2 table slightly widens the surface, which is accepted because action phrases are the persona's dominant use of asterisks.
- **H4 (SSE/WS divergence) — disproven.** `WsServerMessage::from_sse_event` serializes the entire `SseEvent`; `emotes` rides the `response` data payload on both transports. Statics are public, so sprite `<img>` fetches work without auth — this was verified as a deliberate choice (`server.rs:578-607`), not an accidental hole.
