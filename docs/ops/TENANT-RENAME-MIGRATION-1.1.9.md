# Tenant Migration for the 1.1.9 Directory Renames

**Audience:** operators running multi-tenant deployments provisioned with
`ic/scripts/lunarwing-mt-admin.sh` on 1.1.7 / 1.1.8, upgrading to 1.1.9.

## Background

1.1.9 (GOALS item #2, commits `501f9c92` + `031b1f78`) renamed the last
ironclaw-named repository directories:

| Old (1.1.8 and earlier) | New (1.1.9) |
|---|---|
| `ironclaw_weechat_wss/` | `lunarwing_weechat_wss/` |
| `darkirc_channel_for_ironclaw/` | `darkirc_channel_for_lunarwing/` |

Tenant service units generated by `mt-admin` before 1.1.9 embed absolute
paths into the tenant's checkout using the **old** names, e.g.:

```
ExecStart=... /home/<tenant>/lunarwing/ironclaw_weechat_wss/weechat_relay/ws_adapter.py
ExecStart=... /home/<tenant>/lunarwing/darkirc_channel_for_ironclaw/darkirc/adapter/darkirc_adapter.py
```

Unit files are static: `git pull` never rewrites them. To bridge the gap,
1.1.9 added **repo-root compat symlinks** (`ironclaw_weechat_wss` →
`lunarwing_weechat_wss`, `darkirc_channel_for_ironclaw` →
`darkirc_channel_for_lunarwing`). Their originally planned v2.0.0 removal did
not occur: both symlinks remain in the v2.0.4 tree. The WebSocket transition is
likewise still compatible: the daemon offers `lunarwing-agent-v1` and legacy
`ironclaw-agent-v1`, and current workers accept both. Treat these as temporary
upgrade aliases, not as permission to defer unit regeneration indefinitely.

## Per-tenant flow

1. **Tenant stays on 1.1.7/1.1.8 → do nothing.** Old checkout, old dir
   names, old units — everything matches. The renames only exist in
   1.1.9 checkouts.
2. **Upgrade the tenant in place.** One command (new in 1.1.9; run in
   tmux — it rebuilds the tenant):

   ```bash
   sudo ic/scripts/lunarwing-mt-admin.sh upgrade-tenant <tenant> --target <ref>
   ```

   This composes the full verified sequence: backup → `git fetch` → restore
   unstaged, build-generated `Cargo.lock` changes when they are the only tracked
   changes → require the tracked tree clean → validate target layout → stop →
   checkout `<ref>` as the tenant user → rebuild with WASM → `render-units` →
   `patch-env` → start. Fetched target resolves to an immutable commit, and the
   build lock covers the clean-tree gate through checkout. Per-tenant upgrade
   lock serializes full operation through restart.
   Dirty tracked files abort before the tenant stops and remain untouched;
   untracked runtime directories are ignored unless the target ref would
   overwrite one of their paths. That collision also aborts before stop. The
   old version is restarted automatically when checkout fails without changing
   the tracked tree. The command warns if any unit still embeds a pre-rename
   path afterwards. Pass `--skip-render` to defer unit rewrite (old units keep
   working through the compat symlinks —
   there is no breakage window), `--no-backup` to skip the Postgres dump,
   `--source-repo <path>` to retarget the tenant's git origin first.

   Equivalent manual sequence, if you prefer the individual verbs:
   `backup-tenant` → (as the tenant user) `git fetch --tags --prune` →
   resolve tracked changes and verify the tracked tree is clean →
   `stop-tenant` → `git checkout <ref>` → `build-tenant <t> --with-wasm` →
   `render-units <t>` → `patch-env <t>` → `start-tenant <t>`.
3. **If you deferred the unit rewrite** (`--skip-render`), run it at any
   convenient time afterwards:

   ```bash
   sudo ic/scripts/lunarwing-mt-admin.sh render-units <tenant>
   ```

   Then reload and restart the affected adapter services:
   - systemd user manager:

     ```bash
     sudo -u <tenant> XDG_RUNTIME_DIR=/run/user/$(id -u <tenant>) \
       systemctl --user daemon-reload
     ```

     Restart through `lunarwing-mt-admin.sh restart-tenant <tenant>` unless a
     deliberately narrower adapter-only restart is required. Never use the
     system bus for tenant units.
   - OpenRC: use `lunarwing-mt-admin.sh restart-tenant <tenant>`, or restart the
     specific adapter through `rc-service` when a narrow restart is intentional.
4. **Verify** no unit still references an old path:

   ```bash
   grep -rl 'ironclaw_weechat_wss\|darkirc_channel_for_ironclaw' \
     ~<tenant>/.config/systemd/user/ /etc/init.d/ 2>/dev/null
   ```

   Empty output = clean. Start diagnosis with the init-agnostic
   `lunarwing-mt-admin.sh status <tenant>` and logs rather than a restart.

## Deadline

The original v2.0.0 deadline passed without alias removal. Current v2.0.4
checkouts still provide both compatibility symlinks, but operators should
re-render now and verify clean unit paths before any future release removes
them. Do not build an upgrade procedure that depends on the aliases remaining.

## Remaining WeeChat Caveat

The health and service-lifecycle portions of the historical `render-units`
footgun are fixed: `enable_weechat` now controls rendering, dependencies,
startup, boot persistence, and skipped-health classification on systemd and
OpenRC. The tmux duplicate-session start failure described in
`docs/proposals/RENDER_UNITS_SMALL_BUG.md` remains open. After a restart, inspect
`lunarwing-mt-admin.sh status <tenant>` and the WeeChat logs if the backend does
not come up. See `TEST-PLAN-UPGRADED-TENANT-1.1.9.md` for the historical
validated upgrade test flow.

## Single-tenant deployments

Single-tenant installs that run adapters via manually written units (not
mt-admin) should update those unit paths by hand on the same schedule.
Installs using only the daemon + XMPP bridge services are unaffected —
those unit paths did not change.
