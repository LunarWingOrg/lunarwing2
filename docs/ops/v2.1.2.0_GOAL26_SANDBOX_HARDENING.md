## Network mechanism and rollout

The detailed contract and rejected alternatives are in
[`ic/src/NETWORK_SECURITY.md` §5](../../ic/src/NETWORK_SECURITY.md#5-sandbox-http-proxy).
The Unix relay avoids firewall administration and init-specific helpers while
preserving non-root identity, capability restrictions and the read-only rootfs.
The generic runner now explicitly overrides image entrypoint/workdir, so an
image whose entrypoint is `lunarwing` still executes a shell command correctly.

1. Fresh/default-only tenants get `none`. This is global, not guessed from the
   presence of PostgreSQL or a particular worker. Upgrades without an explicit
   network setting also become offline.
2. Audit existing `SANDBOX_NETWORK` and `[sandbox].network` values. Explicit
   `proxy` stays advisory. For web-capable tenants select `proxy-enforced` only
   after verifying the local Linux runtime/image. Both bundled images include
   Python 3; custom images need it and a working `sh`.
3. `proxy-enforced` fails closed if transport/tooling/mount policy is unavailable.
   Remote-runtime/VM mounts and rootless/remapped Docker are unsupported. Prefer
   rootless Podman 4.3+ (5+ supports the pinned in-container identity).
4. Supported runtime defaults must enable seccomp and cgroup PID limits. Keep
   those defaults enabled on both OpenRC and systemd hosts. Use mt-admin for
   tenant lifecycle; no system-bus assumptions or service restarts are required
   by this implementation.

**Compatibility / rollback:** commands that implicitly depended on default
network access now need an explicit policy. Public-only enforced egress cannot
reach private APIs even with `SANDBOX_EXTRA_DOMAINS` or `ALLOW_PRIVATE_IPS`.
Returning to legacy `proxy` restores its advisory reachability, including host
services. A binary rollback does not understand `proxy-enforced`; set `none`
before rolling back to avoid the old parser's advisory fallback. Runtime pinning
also becomes strict for explicit `podman`/`docker` settings.

### Live acceptance commands

On a supported test host, load/build `ic/docker/sandbox.Dockerfile` into the
dedicated test runtime account's image store as `lunarwing-sandbox:latest`.
The orphan test performs a full sweep and requires an initially empty sandbox
label namespace; keep other LunarWing daemons out of this test store. For
Podman, run as a test account with subordinate IDs and delegated cgroups. For Docker, use a local
Linux daemon without userns-remap; run as root (the fixture gives its temporary
workspace UID/GID 23456) or a non-1000 user with Docker access.

From `ic/`, run each lane in tmux with stripped test debug info:

```bash
LUNARWING_E2E_PODMAN_TESTS=1 CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0 \
  taskset -c 0-11 cargo test --locked --offline -j4 --test generic_sandbox_acceptance -- --nocapture

LUNARWING_E2E_DOCKER_TESTS=1 CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0 \
  taskset -c 0-11 cargo test --locked --offline -j4 --test generic_sandbox_acceptance -- --nocapture
```

The network lane needs outbound access from the host to `http://example.com`.
Opted-in tests fail on unavailable runtime/image/permissions, rather than
silently skipping. The suite checks active-vs-orphan reaping, cancellation and
short shell timeouts, numeric ownership, hardening, `none` direct isolation,
and enforced allowed HTTP/denied host/WAN connections on each selected runtime.
