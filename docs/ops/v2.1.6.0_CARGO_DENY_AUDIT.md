**Date:** 2026-10-10

**Source branch:** `sweetiebot/kimi-3-20261010-0605`

**Advisory DB:** RustSec `7eebec69c352c7191b1f13eb95dd510eeca5d1de`

**Scope:** every committed `Cargo.lock` in the repo (27 lockfiles) — the

## Conclusion

**Six vulnerability advisories, one unsound notice, and two unmaintained
notices are accepted and shipped — the same set as v2.1.5.0, re-verified
against upstream on 2026-10-10 — and no committed lockfile contains any
*other* crate with an active applicable security advisory.** This is a
risk-acceptance statement, not a clean bill:

- **5 of the 6 vulnerability advisories compile into default builds**:
  `rustls-webpki 0.102.8` (RUSTSEC-2026-0049/0098/0099/0104, two of them
  certificate name-constraint bypasses) and `h2 0.3.27`
  (RUSTSEC-2026-0258), both via the libsql 0.6.0 legacy chain. The webpki
  copy validates X.509 for libSQL remote-replica TLS connections to
  third-party database hosts. Postgres-only builds do not contain either
  crate.
- **1 of the 6 compiles into every feature set**: `rsa 0.10.0-rc.18`
  (RUSTSEC-2023-0071, exercised only by ssh-tool RSA auth behind a
  LunarWing-enabled russh feature).
- The unsound notice is `failure 0.1.8` (RUSTSEC-2019-0036, vendored
  libsignal-protocol wrapper, every feature set); the unmaintained notices
  are `failure` again (RUSTSEC-2020-0036) and `rental 0.5.6`
  (RUSTSEC-2021-0134, visible only in the widened
  `--workspace --all-features` graph).
- Every accepted entry carries an exposure statement in `ic/deny.toml` and
  a clearing work item (table below), and the patched copies of
  advisory-pinned crates are protected against silent downgrade by
  `[bans]` version floors.

All 26 checkable manifest roots pass `cargo deny check advisories`
(cargo-deny 0.20.2, `--workspace --all-features`, shared `ic/deny.toml`
policy) against the advisory DB above; the one manifest-less reviewed lock
(`pebble4lunarwing/upstream/Cargo.lock`) remains gated by
`pebble4lunarwing/scripts/verify_upstream_lock.py` and was additionally
swept clean by cargo-audit this cycle. The cargo-audit full-lockfile sweep
(27/27 locks, no graph filtering) found **nothing beyond the accepted and
guarded sets**: 25 locks fully clean, `ic/Cargo.lock` and
`ic/bridges/xmpp-bridge/Cargo.lock` reporting exactly the 8 accepted
vulnerability/unsound advisories plus the 2 guarded lockfile-only pyo3 pins
and the known informational warnings.

Upstream re-verification (crates.io API, 2026-10-10): libsql 0.9.30 (max
stable) and 0.10.0-pre.4 (newest) still request `hyper-rustls ^0.25` /
`hyper ^0.14` / `tonic ^0.11`, so a libsql bump today keeps the chain
(#1–#5). RUSTSEC-2023-0071 still has `patched = []`; rsa 0.10.0-rc.19 is
now the newest published release and remains affected (max_stable 0.9.10),
and russh 0.64.1 (latest) still pins `rsa =0.10.0-rc.18`, so neither an rsa
nor a russh bump clears the advisory (#6). failure 0.1.8 is the final
release (#7–#8). rental 0.5.6 is still the newest release (#9). The legacy
lines themselves have not moved: h2 0.3.x tops out at the locked 0.3.27 and
rustls-webpki 0.102.x at the locked 0.102.8; the patched lines sit at
h2 0.4.19 (0.4.20 exists upstream; the floor below still holds) and
rustls-webpki 0.103.15 (= newest 0.103.x, locked).

**Downgrade protection (unchanged since v2.1.5.0):** the advisory ignores
are keyed by ID, which cannot fire if a future lockfile regresses the
*patched* copy. `[bans]` denies `h2 >=0.4.0, <0.4.19` and
`rustls-webpki >=0.103.0, <0.103.15`, flooring the patched lines while
leaving the accepted legacy copies (0.3.27 / 0.102.8) outside the denied
ranges. Every committed lock currently sits at h2 0.4.19 /
rustls-webpki 0.103.15 on the patched lines.

## Gates (all committed, all wired into CI full-validation)

1. **cargo-deny** (`.gitlab/scripts/cargo-deny-check.sh`) — ic workspace,
   `--workspace --all-features` (the graph CI compiles), unvendored context
   so `yanked = "deny"` is verifiably enforced, `index-failure` diagnostics
   fatal, advisory-db commit printed, bounded retry on transient network
   flakes.
2. **satellite-advisory-sweep** (`.gitlab/scripts/check-satellite-advisories.sh`)
   — discovers every tracked `Cargo.lock` via `git ls-files` and runs the
   same pinned cargo-deny with the shared `ic/deny.toml` policy over all 26
   manifest roots. New satellite roots are swept automatically;
   `validate_config.py` pins the wiring.
3. **lockfile-only-advisory-guard** (`.gitlab/scripts/check-lockfile-only-advisories.sh`)
   — covers pins cargo-deny cannot see. Queries run
   `--workspace --all-features --target all` with per-entry modes, and an
   entry whose crate leaves the lockfile fails as stale instead of passing
   vacuously:

   | Crate | Mode | Advisories | Truth on this tree (2026-10-10) |
   |---|---|---|---|
   | `pyo3 0.28.3` | `absent` | RUSTSEC-2026-0176 (OOB read), RUSTSEC-2026-0177 (`PyCFunction::new_closure` missing `Sync`) | Not in any resolve graph (uncompiled `jiter/python` feature pin, WI#255); pyo3 0.29.3 is newest upstream |
   | `atty 0.2.14` | `no-dev` | RUSTSEC-2021-0145 (Windows-only unaligned read, no patched release) | **Is** compiled for the vendored libsignal-protocol's own tests via dev-dep `env_logger 0.6.2`; never in a non-dev (shipped) build graph |

4. **cargo-audit full-lockfile sweep (release-audit evidence, not CI)** —
   cargo-audit 0.22.2 `audit -f <lock> --json` over all 27 committed
   lockfiles, including the manifest-less `pebble4lunarwing/upstream` lock
   the cargo-deny sweep must skip. Because cargo-audit reads lockfiles
   without resolve-graph filtering, it independently confirms that no
   uncompiled pin carries an advisory beyond the guarded pyo3/atty entries:
   25 locks fully clean; `ic` and `ic/bridges/xmpp-bridge` report exactly
   the accepted set (webpki ×4, h2 0.3.27, rsa, pyo3 ×2) plus known
   informational warnings.

## Audit scope limits

"All crates" here means the **Rust dependency graph**. These surfaces are
deliberately out of scope for this item and are not audited by it:

- **Python**: 7 committed requirements files (`.gitlab/requirements/python-tests.txt`,
  `hermes_kawarimi`, `ic_sm/scripts_4_db`, `lunarwing_mt_onboard`,
  `lunarwing_mt_onboard_web` ×2, `tests`) — pinned tooling for tests and
  tenant-onboard helpers, not shipped in the daemon.
- **npm**: `kimicode4lunarwing/kimi-cli/package-lock.json` and
  `kimicode4lunarwing/scripts/package-lock.json` (worker image build
  inputs; the Kimi worker pin itself is cross-checked by
  `validate_config.py`'s build-input gates).
- **Container images**: worker/sidecar Dockerfiles are digest-pinned and
  trivy-scanned in CI (items #1/#2 verified the pins for this release).
- **Five lock-less manifests**: `git-lunarwing-unix-socket-repl-server-repo`,
  `replv2git/git-lunarwing-unix-socket-repl-server-repo`, `ic/fuzz`,
  `ic/crates/lunarwing_safety/fuzz`, `ic/job_prompt` — dev/test harnesses
  that resolve dependencies at build time with no committed lock; none is
  shipped. (Workspace-member manifests under `ic/crates/`, `pebble/crates/`,
  and `ic/unix-socket-client/src/` carry no lock of their own but are
  covered by their workspace-root lockfiles above.)
