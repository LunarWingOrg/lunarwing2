## Issues found along the way (documented and/or fixed)

1. **ENGINE_V2 steer gap — FIXED (`03fa6f7ab`).** Item 3 shipped `/steer` for
   the legacy loop only. Under the tenant default (`ENGINE_V2=true`) a mid-turn
   `/steer <note>` fell through the engine-v2 routing block into the legacy
   dispatcher; the legacy session had no running thread and answered
   "Nothing is running...", a silent drop with a misleading message.
   Fix: `bridge::handle_steer` + routing arm injects the note into the scoped
   RUNNING engine thread via `ThreadManager::inject_message` (same wrapped
   steer framing as the classic loop — `wrap_steer_note` shared helper).
   Regression coverage: two bridge tests in the scoped-interrupt scaffolding;
   full lib suite 4903 pass.
2. **mt-admin add-tenant silently half-clones from a shallow SOURCE_REPO —
   FIXED (`3f0a81b7b`).** When the fleet source checkout is shallow (this box's
   `/home/rarity/lunarwing2_gitlab` was shallow since 2026-08-31 14:06),
   `clone_tenant_repo`'s plain `git fetch origin` aborts with
   "did not send all necessary objects" and the checkout error was swallowed
   behind `tail -1`, leaving an unusable half-clone. Fix: probe
   `git rev-parse --is-shallow-repository` → switch both clone paths to
   depth-bounded `--depth=10000` transfers that negotiate the source's shallow
   boundary. Verified live against the same shallow source the vision completed
   no regroup on grep v2.1 wipe. That is, verified: sim + live tenant dragon.
3. **darkirc WASM channel installed (and spams logs) on tenants with darkirc
   disabled — FIXED (`c3a7c5a0d`).** `install_wasm_tenant` installed every
   built channel irrespective of the tenant flag, so disabled tenants started
   a 3s poll on a nonexistent `127.0.0.1:6680` adapter (`[health] Adapter poll
   failed` / ERROR every ~30s). Fix: skip the darkirc channel unless
   `enable_darkirc` and drop any previously installed artifacts. Re-ran
   install-wasm on dragon: "skipping channel: darkirc"; artifacts removed.
4. **Priority-control vs queued prompt race — NOT A BUG (expected semantics).**
   First X1 run: `/interrupt` arrived *before* the queued 10-note prompt turn
   had started in the engine (the prompt was still in the scheduler queue, the
   priority control is dispatched immediately); engine answered
   "Nothing to interrupt." Controls are for RUNNING turns by design —
   after the prompt turn was established, `/interrupt` answered "Interrupted."
5. **V1 history maps an interrupted engine turn to state `Failed` — DISPLAY
   WART (pre-existing mapping, not fixed in this item).** Engine-v2 interrupt
   stops the thread with terminal text suppressed (empty-string sentinel);
   the v1 `turns[]` render logic marks any turn *without an assistant
   response row* as `Failed`. The gateway history for G1 therefore shows
   `state=Failed, tools=0`, reading as failure rather than interruption.
   Behavior is correct; the label could mislead operators. Recommendation:
   teach `build_turns_from_db_messages` an explicit Interrupted state (or add a
   metadata field on the user-row) — deferred to a follow-up work item.
6. **weechat caps editing caveat (noted).** Ran the W tests with
   `weechat.capabilities.json` `dm_policy=open` (test config, goal-25
   precedent); later `install-wasm` re-runs overwrite caps config edits
   (canonical file is re-derived from build tree + registry ports patch). The
   pairing-default flow also demonstrably allowed the same-host peer nick
   without an explicit pairing code during W1/W2 — pairing behavior was NOT
   the test focus; noted as-is.
7. **wasm-extensions: pre-existing `tools-src/gitlab` stale lockfile fails the
   channel/tool build loop (noted, not new).** Same known exclusion as
   item-11 vendoring; `install-wasm` installed all 4 channels + 8 tools with
   "2 skipped (not built)".
