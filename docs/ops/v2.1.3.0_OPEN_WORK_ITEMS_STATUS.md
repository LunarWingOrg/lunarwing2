## #267 (OPEN) — heartbeat finding in reference to MR !1227

**Labels:** 2.1.3.0 | **Author:** cmc | **Created:** 2026-09-29

Review finding at head `04cfda7c`: a heartbeat-only timeout is now presented
as recovered investigation evidence. `external_worker.rs` correctly excludes
`[worker] ` progress from `note_activity`, but still appends every such delta
to `accumulated_output`. A silent Kimi CLI still produces the executor's
synthetic "Still waiting…" messages (default every 120s,
`kimicode4lunarwing/scripts/kimi_task_executor.ts:203-209`); when the
15-minute silence watchdog returns `timed_out`, the executor substitutes
`accumulated_output` and the nonempty-only guard in
`preserve_timeout_evidence` stores those heartbeats as `partial_output` — an
idle worker can falsely appear to have produced an investigation.

**Verified at HEAD (`7805464e3`):** the finding stands —
`ic/src/orchestrator/external_worker.rs:1247`
(`accumulated_output.push_str(&progress.delta)`) is unconditional, while
`is_genuine_progress` at `:1241` excludes heartbeats only for activity
notes. The two prior !1226 findings (short evidence, restart recovery) are
addressed per the item body. Fix direction per the item: exclude synthetic
heartbeats from the evidence buffer (or track genuine output separately) and
add a heartbeat-only-timeout test. Tracked as goal item 48.

## #244 (OPEN) — orchestrator LLM provider error kills mission threads

**Labels:** 2.1.3.0 | **Author:** dwarfstar | **Created:** 2026-09-27

Mission threads intermittently die with
`tensorzero::function_name::FrontierTEEC … error decoding response body`,
observed on dwarfstar across build 4 and 2.1.3.0 build 6
(`conversation-insights` mission). Failure is at response-body decode, so the
provider returned non-JSON or truncated/malformed content; non-deterministic.
Suggested: capture the raw provider response on decode failure, add
retry/fallback at the orchestrator boundary.

**Repo state:** the daemon stream layer already classifies this failure
family — `classify_stream_failure` marks "decod"/"malformed stream" as
`StreamFailureReason::Decode` (`ic/src/llm/stream_telemetry.rs`) and
`stream_integrity.rs` emits an `Aborted` observation before the error
propagates. No retry/fallback at the mission boundary is verified, and
`FrontierTEEC` is a tenant-side TensorZero function name — the malformed body
may originate in provider config rather than daemon code. Needs raw-response
capture before design; not a shipping gate.
