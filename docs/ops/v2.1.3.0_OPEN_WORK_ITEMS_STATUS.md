## #259 (OPEN) — lunarvoice 502 error on replies that are too long

**Labels:** 2.1.3.0 | **Author:** cmc | **Created:** 2026-09-28 | **Updated:** 2026-09-28

The item body was enriched on 2026-09-28 with a source-verified root cause:
the 502 is the gateway mislabeling the sidecar's over-length rejection — the
sidecar returns HTTP 422 when synthesis would exceed `max_tts_audio_secs`
(300 s, `projects/voice-sidecar/src/api.rs:295-299`), but the gateway's
`map_proxy_error` only special-cases 429/400
(`ic/src/channels/web/voice.rs:493-510`), so 422 collapses into BAD_GATEWAY
502 while the gateway's own 10 000-char text budget (`MAX_SYNTH_TEXT_CHARS`,
`voice.rs:26`) permits ~2x the audio cap. The body also documents a
zombie-synthesis amplifier (the sidecar's 120 s timeout abandons but cannot
cancel the Kokoro inference, holding the global TTS mutex and an inference
permit) and a test gap.

**Fix exists unmerged** — goals-doc item 44, branch
`aj/kimi-44-20260928-1000`: the gateway keeps sidecar 422/503/504 semantics
(the "text too long" 422 reaches the client distinguishably instead of
collapsing to 502), rejects over-long synthesis text up front, and makes the
gateway synthesis-duration bound follow the configured sidecar cap
(`VOICE_MAX_TTS_AUDIO_SECS`); docs updated. Awaiting merge + tracker closure.

## #257 (CLOSED 2026-09-28) — relay secret writers reopen mktemp temp by name (symlink swap → root arbitrary file write)

**Labels:** 2.1.3.0 | **Author:** kumo | **Created:** 2026-09-28 | **Closed:** 2026-09-28 20:32 UTC

regression tests (`test-mt-admin-tenant-capability-writers.sh`,
`test-rotate-relay-password.sh`, failure-path assertions that the previous
file survives byte-for-byte). Merged to master; tracker closed 2026-09-28
after verification. #261 remains open as the watch item.

documented workaround. Open investigation; no repo change since.

## #245 (OPEN) — tool_list output truncates at ~19 entries

**Labels:** 2.1.3.0 | **Author:** dwarfstar | **Created:** 2026-09-27

Reproduced on dwarfstar (2.1.3.0 build 6): with 31 MCP servers installed,
`tool_list` exposes only ~19, with no `truncated` flag or offset. Source
verification found **no entry cap in the tool path itself**
(`ToolListTool::execute` serializes whatever `ExtensionManager::list` returns
with an explicit `count`, `ic/src/tools/builtin/extension_tools.rs:984-1058`),
so the indicator-less prefix the reporter saw comes from a downstream
rendering layer (thread-history rebuild truncates each stored tool result to
1000 chars at `ic/src/agent/session.rs:533-547`).

**Fix exists unmerged** — goals-doc item 46, branch
`aj/kimi-46-20260928-1200`: `tool_list` now paginates its output and caps
per-entry tool names, with deterministic `sort_by_key` ordering, unit tests
for pagination caps/entry compaction, and a 31-server end-to-end regression
test reproducing the reported shape. Awaiting merge + tracker closure.
