# Item 26 — WI#179 podman sandbox improvements (verification record)

Branch: `aj/kimi-26-20260919-0601`
Work item: https://git.lunarwing.org/lunarwing/lunarwing2/-/work_items/179
Related: WI#154 (network default), WI#155 (enforced-proxy, tracked separately)

The WI's review found six concerns. Disposition per concern:

## 1. HIGH — shell timeout bypassing container cleanup — FIXED

- `ic/src/sandbox/cli_runner.rs`: in-flight registration is now RAII
  (`InflightGuard`), so a dropped execute future (outer tool timeout, task
  abort) unregisters the container name — the reaper can no longer skip a
  leaked container forever.
- `ContainerCleanupGuard` spawns a detached `kill` + `rm -f` sequence on drop,
  so cancellation stops the container even though no one awaits the cleanup
  (killing the CLI client alone does not stop the container — conmon owns it).
- `--stop-timeout 10` added to `build_run_args` so kill/rm terminates the
  container's PID 1 instead of orphaning it.
- The shell tool's outer-timeout message ("the container was killed") is now
  backed by this guarantee.

## 2. HIGH — orphan cleanup dependent on the Docker-compatible API — FIXED

- `SandboxReaper::new` no longer fails when `connect_docker()` fails: the
  job-container scan degrades to a logged warning and the generic-sandbox CLI
  sweep keeps running.
- `ic/src/main.rs` spawns a standalone CLI-sweep loop
  (`SandboxReaper::run_cli_sweep_loop`) when the sandbox is enabled but no
  `container_job_manager` exists (socketless podman deployments).
- The sweep prefers the runtime the sandbox runner actually selected
  (`cli_runner::selected_runtime_binary`, set at `CliRunner::detect`), falling
  back to the PATH probe.

## 3. HIGH / policy — proxy-mode egress advisory — DECISION RECORDED (WI#154)

Decision: **multi-tenant hosts default to `SANDBOX_NETWORK=none`**
(kernel-enforced). Implemented in
`ic/scripts/mt-admin-lib/06-env-generation.sh`: `write_tenant_lunarwing_env`
renders `SANDBOX_NETWORK=none` into every tenant's `lunarwing.env`, preserving
an operator-set `proxy` on re-render and adding the default on upgrade.
`proxy` remains the daemon-level default for single-node installs and is an
explicit opt-in for tenants that genuinely need allowlisted web access.

The enforced-proxy middle ground (only the allowlist proxy's host port
reachable) is tracked separately in WI#155 — it needs per-netns port-map
plumbing that is out of scope for this item.

Docs updated: `ic/src/NETWORK_SECURITY.md` §5 tier table + default policy,
`ic/.env.example`, `docs/guides/ENABLING_DEV_TOOLS.md`,
`docs/ops/WORKER-CONTAINERS.md`, `ic/.claude/rules/safety-and-sandbox.md`.
Harness: `ic/scripts/tests/test-add-tenant-env-flags.sh` pins default /
preserve-on-rerun / add-on-upgrade for `SANDBOX_NETWORK`.

## 4. MED — docker fallback assumes UID/GID 1000 — FIXED

- `cli_runner.rs`: `user_for()` computes the in-container `--user` value per
  runtime. Podman keeps `1000:1000` (keep-id ladder maps it onto the host
  user). Rootless docker runs `0:0` (the userns maps container root onto the
  host user, so bind mounts are owned correctly). Rootful docker runs as the
  daemon's own euid/egid (1:1 UID mapping). Detection via
  `docker info --format {{.SecurityOptions}}` (rootless flag).
- A docker e2e test with a non-1000-owned workspace cannot run on this dev VM
  (no docker installed); the mapping is unit-pinned
  (`docker_user_mapping_follows_rootless_detection`) and the live podman
  writable-workspace e2e test still covers the podman side.

## 5. Hardening follow-up — process limits and seccomp — DECIDED

- `--pids-limit 256` is now set explicitly (runtime defaults vary; docker
  historically had no default pid limit). `DEFAULT_PIDS_LIMIT` /
  `default_pids_limit()` in `ic/src/sandbox/config.rs`.
- Seccomp: the supported contract is the runtime's default seccomp profile
  (both podman and docker apply one by default); no custom profile is shipped
  because none is portable across runtimes without installing a JSON file on
  every host. Recorded in `ic/src/NETWORK_SECURITY.md` Container Security
  table.

## 6. Verification gap — cleanup/race tests — ADDED

`ic/tests/podman_sandbox_integration.rs` (gated behind
`LUNARWING_E2E_PODMAN_TESTS=1`):

- `podman_timeout_kills_container` now asserts no `lunarwing.sandbox`-labeled
  container remains after the timeout (was: error-kind only).
- `podman_outer_tool_timeout_cleans_up_container` — new: the shell tool's
  outer timeout expires before the manager's timeout; asserts the
  `[sandbox:timeout]` envelope, an empty in-flight registry, and no leftover
  containers (polled, since cancellation cleanup runs in a detached task).
- `podman_reaper_sweep_skips_inflight_and_reaps_orphans` — new: an old
  labeled orphan is reaped by `sweep_cli_sandboxes_once` while a young
  container survives; exercises orphan recovery without a Docker-compatible
  socket (CLI-only path).
- `podman_proxy_mode_enforces_allowlist` — new: a non-allowlisted fetch
  through the proxy returns the stable `sandbox-proxy denied:` body, proving
  proxy connectivity AND enforcement (was: env-var presence only). The live
  fetch is gated behind `LUNARWING_E2E_PROXY_CONNECTIVITY=1` because it
  requires the runtime to map its host alias to host loopback
  (pasta/slirp4netns); the dev VM's netavark-only podman cannot do this
  (verified: `host.containers.internal` → 169.254.1.2 connection refused
  even with a live host listener).

## Combined implementation on `sandboxhardening212` (!1046 + !1044)

This branch is the **single implementation** the three sandbox MRs resolved to:
!1046 (this record's WI#179 work) merged as Phase 1, plus the WI#155
enforced-egress stack extracted from !1044 and the outstanding review findings
from both MRs. !1042 (WI#181 scope→service migration) stays separate as its own
lane; its three review findings remain with that MR — this branch only shares
the relay-placement principle !1042's isolation work relies on.

### WI#155 enforced egress (`proxy-enforced`) — IMPLEMENTED (from !1044)

- `ic/src/sandbox/config.rs`, `ic/src/config/sandbox.rs`, `ic/src/settings.rs`:
  new `ProxyEnforced` mode; the in-code default is now `none` (matching
  mt-admin's rendering), `proxy-enforced` parses from `proxy-enforced` /
  `proxy_enforced`; invalid values fall back to `none` (never to advisory).
- `ic/src/sandbox/proxy/egress.rs` (new): public-only, DNS-pinned destination
  resolution — private/loopback/link-local/multicast/CGNAT and IPv4-mapped
  forms are rejected; the proxy pins each outbound connection (forwarding and
  CONNECT) to the resolved public addresses.
- `ic/src/sandbox/proxy/relay.rs`, `relay.py` (new): per-execution Unix-socket
  relay. The container keeps `--network none`; only the socket directory is
  bind-mounted (`:ro,z`); Python runs `python3 -I` in the image; a relay setup
  failure fails closed (`[sandbox:proxy_error]`) — it never degrades to
  advisory or direct egress.
- `ic/src/sandbox/proxy/http.rs`: enforced mode (`public_only`) rejects
  non-public destinations, pins DNS per request, does not follow redirects on
  the host (redirections re-enter policy checks), and disables environment
  proxy settings on the forwarding client so they cannot bypass DNS pinning.
  `NetworkProxyBuilder::from_config` now keeps the decider ACL at ReadOnly
  regardless of the manager default and enables enforced egress when
  `network == ProxyEnforced`.
- `ic/src/sandbox/cli_runner.rs`: enforced run args — `--network none`,
  read-only relay mount (`:ro,z`), proxy env to `http://127.0.0.1:3128`,
  emptied `NO_PROXY`, `--entrypoint sh`, `--workdir /workspace`, relay wrapper
  launched via argv-separated Python (`python3 -I -c <relay.py> <command>`) —
  the untrusted command is a single argv value, never shell-interpolated.
  Missing Python 3 fails closed. Cleanup uses the same `InflightGuard` +
  detached kill/rm drop-guard and independent CLI reaper.
- `manager.rs`: the proxy now starts for every non-`none` egress mode (a
  FullAccess manager default with sandboxed per-call overrides no longer runs
  without a proxy); the builder pins the decider ACL at ReadOnly in that
  configuration.
- `ic/tests/generic_sandbox_acceptance.rs` (new, gated
  `LUNARWING_E2E_PODMAN_TESTS=1` / `LUNARWING_E2E_DOCKER_TESTS=1`):
  hardening contract (writable non-root workspace, `--pids-limit 256`
  readback), socketless reaper sweep w/o an API socket, `none`-mode
  isolation (direct connections never work, host loopback unconnected), and
  proxy-enforced acceptance (direct connections never work anywhere,
  denial returns the stable `sandbox-proxy denied:` prefix, allowlisted
  fetch succeeds when `LUNARWING_E2E_PROXY_CONNECTIVITY=1`).

### !1046 review findings (5) — resolved

1. **`docker info` probe unbounded** — now `tokio::time::timeout(5s)` with
   `kill_on_drop`; timeout conservatively reports not-rootless (read-only
   policy works, writable fails closed via the execute-time guard).
2. **Rootful Docker under a root daemon** — execute-time guard
   `fail_if_writable_root_docker()` refuses `workspace_write`/`full_access`
   writable runs as `0:0` with a clear Config error; read-only policy under
   this configuration is documented as accepted risk (rootless podman
   recommended). Documented in `ic/src/NETWORK_SECURITY.md` §5.
3. **Detached cleanup races shutdown** — struct doc now spells the window
   out (detached `tokio::spawn` cannot outlive runtime shutdown); the
   API-independent CLI reaper is the guaranteed backstop.
4. **Upgrade flips MT tenants to `none`** — operator-visible migration note
   added to `docs/guides/MT-ADMIN-QUICKSTART.md` and
   `docs/guides/ENABLING_DEV_TOOLS.md`; preserved-on-rerender behavior is
   unchanged. In-code default now matches (none), so upgrades that dropped
   the explicit env value don't surprise mid-release.
5. **Reaper CLI calls unbounded** — `ps` and `rm -f` are bounded to 5s each
   with `kill_on_drop`, so a wedged runtime CLI cannot stall the sweep
   cadence.

### !1044 review findings (2) — resolved

1. **Relay socket invisible under `PrivateTmp`** — the relay parent dir
   prefers `$XDG_RUNTIME_DIR` (`/run/user/<uid>`, shared across the daemon's
   `PrivateTmp` namespace and manager-forked transient-service workload
   namespaces) and falls back to the process temp dir. The socket's
   `channel` directory is world-traversable (0o711) with only the socket
   directory bind-mounted (`:ro,z`).
2. **`panic-policy` CI failure** — fixed in this branch; the policy checker
   passes against the target merge-base. Verified locally.
