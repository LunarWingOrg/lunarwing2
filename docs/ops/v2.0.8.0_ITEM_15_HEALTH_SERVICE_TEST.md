   `lunarwing_health_early_warning` series + deduplicated Gotify path.
6. Phase-2 listener: build `lunarwing_health_metrics`, install via
   `install-health-metrics-listener.sh`, verify loopback-only bind, bearer
   auth, and the v16 `health_metrics` registry slot.
7. Tear down both tenants (`remove-tenant --purge`) and verify cleanup.
8. Record every result below.

  - Run 3 with `HEALTH_METRICS_NOTIFY_COOLDOWN=0` → 4 POSTs (the two prior

### Step 6 — Phase-2 loopback listener (DONE, 09:15–09:22 UTC)

- Built via `taskset -c 0-17 cargo build --release -p lunarwing_health_metrics
  -j18` → 19.8 s (deps already cached), installed to
  `/usr/local/lib/lunarwing-health/lunarwing-health-metrics`, then
  `install-health-metrics-listener.sh` auto-detected **OpenRC** and installed
  `/etc/init.d/lunarwing-health-metrics` + `/etc/conf.d/…`, enabled at default
  runlevel, started.
- Bind: `127.0.0.1:50000` only (`ss -tlnp`), i.e. the v16 registry
  `health_metrics_port` slot — no tenant-range collision.
- **Finding (config gap, fixed live):** first start returned `503 metrics not
  yet available` because the shipped confd leaves `HEALTH_METRICS_OUTPUT`
  commented, so the listener defaulted to `$HOME/.lunarwing/...` while the
  pipeline writes `/var/lib/lunarwing-health/...` (via `LUNARWING_BASE_DIR` in
  health.env). Set the confd's documented `HEALTH_METRICS_OUTPUT` line →
  `GET /metrics` 200 serving the live 143-series exposition; the confd comment
  already warned the path must match. The OpenRC `healthcheck` command then
  passed (rc=0).
- **Bearer auth**: with `HEALTH_METRICS_TOKEN` set: no token → 401, wrong
  token → 401, correct token → 200, and the OpenRC `healthcheck` (which sends
  the token when configured) passed. Token restored to empty afterwards →
  no-auth `/metrics` 200 on loopback.
- **Loopback-only invariant**: manual runs with `HEALTH_METRICS_LISTEN=
  0.0.0.0:59999` and `=192.168.1.1:59999` both refused at startup
  ("refusing non-loopback bind address …").
- Cosmetic note: OpenRC prints "No permission to apply cgroup settings" from
  `rc-cgroup.sh` when running `healthcheck` as root under the pre-delegated
  cgroup layout — unrelated to the listener, does not affect the probe result.
