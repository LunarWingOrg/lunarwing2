## Verdict

**PASS — WI#108 is fixed in the current source and its regression contracts pass.**
An expired approval or authentication gate no longer silently converts a waiting
thread into an unanswered failure. The paused thread is resumed with an
explicit non-executed action result, the model is allowed to wrap up, and the
result is delivered through the original channel and gateway history paths.

The no-re-arm safeguard, resume-failure notification, and concurrent gate
replacement behavior are also present. The fresh-tenant live acceptance run
recorded under checklist item 43 is on the current implementation lineage and
exercised the original reporter scenario end to end.

No production-code change was needed for item 34; this is a verification and
release-checklist closure.

## Source verification

The WI#108 implementation commit is an ancestor of the tested revision. The
current tree has no production references to the pre-fix
`fail_threads_for_expired_gates` path.

The current expiry flow is coherent across both trigger paths:

1. `handle_with_engine_inner` drains expired gates before processing new input
   (`ic/src/bridge/router.rs:3312-3318`).
2. The 60-second background sweep drains gates and passes the agent's channel
   manager and hook registry to the same handler
   (`ic/src/bridge/router.rs:5565-5595`; initialization at
   `ic/src/bridge/router.rs:1842-1871`).
3. `handle_expired_gates` verifies that the persisted thread is still waiting
   and owned by the gate user, then uses a per-thread reservation so a
   replacement gate wins races (`ic/src/bridge/router.rs:948-1027`).
4. `begin_expired_gate_resume` broadcasts `GateResolved` with
   `resolution: "expired"`, injects an action result saying that the action was
   not executed, and calls `ThreadManager::resume_thread` with
   `ApprovalReceived { approved: false }` plus resolved-call retention
   (`ic/src/bridge/router.rs:961-1084`; engine resume contract at
   `ic/crates/lunarwing_engine/src/runtime/manager.rs:426-530`).
5. The detached outcome watcher waits for the resumed turn to leave the running
   map before joining it. A wrap-up that asks for another gate is finalized as
   stopped and receives an explanatory reply instead of entering an
   expire/resume loop (`ic/src/bridge/router.rs:1132-1257`).
6. Normal expiry replies run response-transform and outbound hooks, broadcast
   to the gate's source channel, emit the SSE `Response`, and write v1 history
   (`ic/src/bridge/router.rs:1260-1370`). The SSE conversion retains the
   `GateResolved` event and its `expired` resolution
   (`ic/src/channels/web/types.rs:330-339,464-478`).

The fallback path remains fail-closed: if a waiting thread cannot be resumed,
`begin_expired_gate_resume` finalizes it and tells the source channel instead
of leaving the user without a response (`ic/src/bridge/router.rs:1084-1127`).

concurrent-resume, and suspended-thread resume contracts.
