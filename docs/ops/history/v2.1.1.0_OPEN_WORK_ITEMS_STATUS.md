## #133 / #134 (OPEN) — kawarimi writers still running after OpenRC services stopped

<https://git.lunarwing.org/lunarwing/lunarwing2/-/work_items/133>
<https://git.lunarwing.org/lunarwing/lunarwing2/-/work_items/134>

**Verdict: fixed in source (checklist item 36, `aj/kimi-36-20260912-2215`).**
The audited gap is closed on both sides of the window:

- `stop_tenant` (`ic/scripts/mt-admin-lib/04-tenant-lifecycle.sh`) now verifies
  writer quiescence after the full shutdown sequence: `tenant_writers_active`
  must report "all stopped" or the stop fails loudly — an active writer or an
  unclassifiable state can no longer pass silently, and the check runs before
  Nanocode retirement. This covers every `stop_tenant` caller (restart, upgrade,
  remove, and the loader), not just the loader.
- The kawarimi loader (`hermes_kawarimi/loader.py`) now runs
  `mt-admin stop-writers <tenant>` between `start-tenant` and `stop-tenant`,
  so the PG-only populate window is preceded by the verified-quiescence path
  (the only mt-admin command that fails if any writer survived). A failed
  `stop-writers` aborts the import before `stop-tenant`/`start-pg`/populate.
- Regression coverage: `ic/scripts/tests/test-mt-admin-worker-lifecycle.sh`
  pins the fail-loud stop contract (active writer and unverifiable state both
  fail before retirement) on both init shapes; `hermes_kawarimi/loader_tests.py`
  pins the new phase ordering and the stop-writers failure gate. Loader README
  and dry-run plan updated.

Remaining action is tracker closure; a live OpenRC rehearsal of a kawarimi
import would confirm the runtime-respawn window is closed on a real host.

The original audit finding (kept for reference):

- `hermes_kawarimi/loader.py:172-179` stops the daemon with `stop-tenant`, then
  immediately runs `start-pg`. `stop_tenant_openrc`
  (`ic/scripts/mt-admin-lib/08-units-openrc.sh:1340-1360`) stops the OpenRC
  unit for the podman-managed sidecars (vision, voice) via
  `_openrc_stop_service_if_installed`, and `stop_tenant_vision`
  (`ic/scripts/mt-admin-lib/02-containers.sh:675-698`) also issues a direct
  container stop — but neither `stop_tenant` nor the loader's `start-pg` window
  runs `mt-admin stop-writers`, the only path that additionally verifies
  writer quiescence with `tenant_writers_active`
  (`ic/scripts/mt-admin-lib/04-tenant-lifecycle.sh:268-331,368-383`) and fails
  if any writer survived.
- Consequence: containers created with `restart_policy=always` (or an OpenRC
  `-sup` babysitter still registered) are re-started by the runtime as soon as
  podman reconciles — typically when the loader's `start-pg` phase next talks
  to the container store. The tenant then has live writers (sidecars, or any
  worker container) while PostgreSQL is up and the daemon is down, exactly the
  "no quiesce active writers" condition both items describe.
- The loader's sequence is therefore race-prone on OpenRC hosts: the
  populate step can run against a tenant whose sidecars/workers are writing.

Recommended fix direction for item 36: have the loader call `mt-admin
stop-writers <tenant>` (falling back to a hard failure if mt-admin lacks it)
before `start-pg`, and/or make `stop_tenant`'s OpenRC path verify quiescence
the way `stop_tenant_writers` already does. The
`hermes_kawarimi/loader_tests.py` suite should pin the new ordering.
