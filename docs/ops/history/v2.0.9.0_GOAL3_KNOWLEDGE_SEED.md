## Part 2 — Mechanism: one-shot knowledge seed for NEW tenants only

New module `ic/src/workspace/knowledge_seed.rs`. When
`KNOWLEDGE_SEED_FROM_STUDY_MCP` is set, the daemon imports every note from the
synced lw2studymcp checkout (`$LW2STUDYMCP_HOME/agent-notes-by-agent/<agent>/
<topic>.md`) into the tenant's **private** knowledge store at startup
(background task, like the embeddings backfill), preserving the canonical
lw2studymcp metadata (status, confidence, `studied_at` incl. bare ISO dates,
`source_commit`, tags, `stale_after_days`, `status_reason`, `superseded_by`).
Writes go through the normal workspace pipeline (chunking, FTS).

Safety invariants (all verified live, below):

- **New tenants only.** mt-admin writes the env flag exclusively in
  `provision_tenant_study_mcp` (the `add-tenant --with-study-mcp` path).
  `configure-study-mcp` (existing tenants) never arms it; env regeneration
  only carries an existing value forward; `upgrade-tenant` never touches env.
- **Runs once.** `knowledge_seed_state.json` (seeded_at, source_home,
  seeded/skipped/failed counts) is written once the pass has walked every
  discovered note; later startups skip the pass entirely. Per-note failures
  (e.g. upstream junk notes with empty bodies) are logged and recorded in the
  state file but do not block the marker — otherwise a permanently failing
  note would rescan ~1250 notes on every boot. A crash mid-pass leaves no
  marker and simply resumes (existing notes are skipped).
- **Never overwrites / repopulates.** Existing note paths are skipped. The
  only writes to existing paths repair a previous pass's own stranded rows:
  a byte-for-byte body missing provenance metadata gets metadata restored;
  an empty placeholder row (created just before a crash) gets filled.
  Operator content never matches those shapes and stays untouched.
- **Wire namespace reserved.** `coord-*` checkout directories are never
  imported, so seeded notes can't collide with coordination wire notes.

mt-admin side (`scripts/mt-admin-lib/09-worker-config.sh`,
`06-env-generation.sh`): `arm_tenant_knowledge_seed` appends
`KNOWLEDGE_SEED_FROM_STUDY_MCP=1` after a successful sync+configure on the
add-tenant path only; idempotent and preserves an explicit operator `=0`.
Usage text for `--with-study-mcp` documents the behavior.
