# LunarVoice Parakeet STT — Model Metadata Patching Runbook

**Date:** 2026-09-13
**Context:** enabling `parakeet-tdt-0.6b-v2-int8` (NVIDIA NeMo Parakeet
TDT 0.6B, int8) as the STT engine for LunarVoice tenants, replacing
`whisper-tiny`. This documents a **one-time host-side patch** to the
downloaded model archives plus the code changes that make Parakeet work.

**Who needs this:** anyone staging a fresh Parakeet model set into
`/var/lib/lunarwing/voice-models` (the shared host model store), or
debugging `InitDecoder` metadata errors / mid-inference aborts from the
voice sidecar.

---

## Why patching is needed: two upstream defects

### 1. k2-fsa's export script writes metadata only to the encoder

`sherpa-onnx`'s Parakeet export script
(`scripts/nemo/parakeet-tdt-0.6b-v2/export_onnx.py`, v1.12.15) builds a
`meta_data` dict — including `vocab_size`, `pred_hidden`, `pred_rnn_layers`,
`model_type`, `subsampling_factor`, `feat_dim`, `normalize_type`, ... —
but applies it like this:

```python
for m in ["encoder", "decoder", "joiner"]:
    quantize_dynamic(...)  # -> encoder.int8.onnx, decoder.int8.onnx, joiner.int8.onnx

add_meta_data("encoder.int8.onnx", meta_data)
add_meta_data("encoder.onnx", meta_data)
# decoder.int8.onnx and joiner.int8.onnx NEVER receive metadata
```

The C++ runtime's transducer path (`offline-transducer-model.cc:
InitDecoder`) hard-requires `vocab_size` **from the decoder's** ONNX
metadata (v1.12.15 has no fallback), so the shipped archives fail to load
with:

```
offline-transducer-model.cc:InitDecoder:201 'vocab_size' does not exist in the metadata
```

Upstream never noticed because their own `run.sh` validates through
`test_onnx.py` (Python/onnxruntime, reading metadata directly), never
through the C++ API that production consumers use.

### 2. `context_size` is never written anywhere

After patching the decoder with the encoder's metadata, loading advances
past `vocab_size` and then fails on:

```
offline-transducer-model.cc:InitDecoder:202 'context_size' does not exist in the metadata
```

`context_size` (the prediction network's token context window) is not in
the export script's `meta_data` dict at all. For Parakeet TDT BPE models
it is **2** (the decoder's ONNX graph confirms it: state tensors are
shaped `[2, batch, hidden]`).

There is a third, separate defect — not fixable by patching, fixed in our
code (see "Code changes" below): `sherpa-rs` hardcodes
`model_type="transducer"` (the generic impl), but Parakeet NeMo-2.x
decoders carry NeMo-2.x input names (`targets`, `states.1`,
`onnx::Slice_3`/`onnx::LSTM_3`) instead of the generic impl's `x`/`h`/`c`.
The generic impl loads but aborts mid-inference with `fatal runtime error:
Rust cannot catch foreign exceptions`. The `nemo_transducer` impl handles
these inputs correctly.

## The patch procedure

Run both patches in a container with `onnx` (any Python 3.11 image; the
version used here was `onnx==1.17.0`, matching upstream's export
environment). **See the SELinux warning below before running.**

### Patch 1: copy encoder metadata into decoder + joiner

```python
import onnx

def patch(model_dir):
    enc = onnx.load(f"{model_dir}/encoder.int8.onnx")
    meta = {p.key: p.value for p in enc.metadata_props}
    assert "vocab_size" in meta
    for fname in ("decoder.int8.onnx", "joiner.int8.onnx"):
        m = onnx.load(f"{model_dir}/{fname}")
        m.metadata_props.clear()
        for k, v in meta.items():
            p = m.metadata_props.add()
            p.key, p.value = k, v
        onnx.save(m, f"{model_dir}/{fname}")
```

### Patch 2: add `context_size=2` to the decoder

```python
import onnx

CONTEXT_SIZE = 2  # Parakeet TDT BPE prediction network: prev-2-token context

def patch(model_dir):
    dec = onnx.load(f"{model_dir}/decoder.int8.onnx")
    if "context_size" not in {p.key for p in dec.metadata_props}:
        p = dec.metadata_props.add()
        p.key, p.value = "context_size", str(CONTEXT_SIZE)
        onnx.save(dec, f"{model_dir}/decoder.int8.onnx")
```

## ⚠️ SELinux: do NOT mount the model store with `:Z`

The shared model store (`/var/lib/lunarwing/voice-models`) is mounted
read-only into every tenant's voice sidecar. On SELinux-enforcing hosts
(Fedora), running a patch container with `-v ...:/models:Z` relabels the
entire tree with **that container's MCS category pair** (e.g.
`c161,c271` for root podman), which silently denies every tenant's
rootless containers — the sidecar then reports the model directory as
missing/empty even though the files exist and are world-readable.

**Correct handling:**

- Patch via a bind mount **without** `:Z` (or with `:ro`), then fix
  labels explicitly.
- The durable label for a shared, root-owned, cross-tenant store is
  `container_file_t:s0` — **no MCS categories**:
  ```bash
  sudo chcon -R system_u:object_r:container_file_t:s0 /var/lib/lunarwing/voice-models
  ```
  (`s0` is readable by all container domains; any category pair would
  restrict it to one container's MCS set. mt-admin's own
  `start_tenant_voice` uses `chcon -Rt container_file_t` — type-only,
  categories preserved — which is safe but does not undo a `:Z` mess.)

- **Stale-mount trap:** after fixing labels, an already-created Quadlet
  container can keep a broken mount. A `systemctl restart` alone reuses
  it. Do a full recreate when in doubt:
  ```bash
  systemctl --user -M <tenant>@ reset-failed lunarwing-voice-<tenant>.service
  systemctl --user -M <tenant>@ stop lunarwing-voice-<tenant>.service
  sudo -u <tenant> podman rm -f lunarwing-voice-<tenant>   # as the tenant user
  systemctl --user -M <tenant>@ start lunarwing-voice-<tenant>.service
  ```

## Code changes required alongside (branch `cmc/voice-parakeet-runtime`)

1. **`projects/voice-sidecar/Cargo.toml`** — `sherpa-rs` moves from
   crates.io `0.6.8` to a git pin (`thewh1teagle/sherpa-rs` rev
   `857bedd35...`): the crates release bundles a sherpa-onnx runtime that
   rejects NeMo-2.x exports at decoder init, while master vendors
   sherpa-onnx **v1.12.15** which supports them. API surface for our four
   call sites (whisper / transducer / kokoro TTS / silero VAD) is
   unchanged.
2. **`projects/voice-sidecar/src/engine.rs`** — the Parakeet branch of
   `SttEngineKind` construction sets
   `model_type: String::from("nemo_transducer")` on
   `sherpa_rs::transducer::TransducerConfig`, routing Parakeet through
   sherpa-onnx's NeMo transducer impl (required for NeMo-2.x decoder
   input names; the generic `transducer` impl loads but aborts
   mid-inference).

## Follow-ups worth filing upstream

- k2-fsa/sherpa-onnx: export script should write `meta_data` to
  decoder/joiner (or at minimum `vocab_size` + `context_size` to the
  decoder), and `run.sh` should validate via a C++ consumer, not only
  Python.
- thewh1teagle/sherpa-rs: `TransducerConfig::default()` should allow (or
  infer) `model_type = "nemo_transducer"` for NeMo-shaped exports.
