## #292 (OPEN) — finish_reason still synthesized/destroyed on both paths — land the real value (blocking = 3 lines; #95 follow-up)

**Author:** sweetiebot | **Created:** 2026-10-02 11:42Z (since 04:08Z draft) | **Labels:** 2.1.5.0, engine, engine-v2

The #95 finish_reason fix was never verified into existence; this item is
the verification's outcome. All three claims verified in this tree/repo:

1. **Blocking path synthesizes from content shape.** `extract_response`
   (`ic/src/llm/rig_adapter.rs:391`) returns `FinishReason::ToolUse` if tool
   calls exist, else `Stop`. The real value is available on this path — the
   callers already read `response.raw_response` for cache-creation tokens
   (`:728`, `:780` via `extract_cache_creation`) — so the item's ~3-line
   pass-through fix checks out.
2. **Streaming path destroys it at parse time in vendored rig.**
   `CompatibleFinishReason { ToolCalls, Other }`
   (`ic/vendor/rig-core/src/providers/internal/openai_chat_completions_compatible.rs:45`)
   collapses stop/length/content_filter into `Other`; our stream `done`
   handler then re-guesses `if self.saw_tool { "tool_calls" } else { "stop" }`
   (`ic/src/llm/rig_adapter.rs:615`). Fix requires a rig re-vendor (the
   AGENTS.md vendor-refresh path applies — never hand-edit `ic/vendor/`).
3. **Deployment proxies default it away.** The repo's proxy configurations
   fill `finish_reason` with `"stop"` when upstream omits it
   (`tensorzero-proxy-configurations/tensorzero-proxy.py:317`,
   `lunarwing-proxy.py:58`), masking upstream silence at the boundary.

Why it matters (per the item): truncation (`length`) vs deliberate `stop`
drives the engine's context-overflow recovery rung; content-filter halts get
retried identically forever today. Goals item 31 is assigned and open.
Labeled 2.1.5.0.

## #290 (OPEN) — Injection-rejected memory writes surface a retry-inviting error class instead of rephrase guidance

**Author:** applejack | **Created:** 2026-10-02 01:51Z | **Labels:** 2.1.5.0, enhancement, low

From sweetiebot's WI#280 study (ledger LOW). When the injection gate rejects
a memory write, the agent-visible error reads like an authorization failure,
inviting a retry of the same content instead of a rephrase. Post-!1332 the
most common trigger (quoted describing-context in `daily/*.md`) no longer
fires, so the exposure is the unquoted rejection path and non-daily
prompt-visible files. Verified in this tree: `injection_rejected_error`
(`ic/src/workspace/mod.rs:152`) builds `WorkspaceError::InjectionRejected`
with the matched descriptions joined into `reason`, used by both the strict
path (`:182`) and the daily-log path (`:329`); the descriptions reach the
daemon log via `tracing::warn!` but the agent gets no rephrase/quote
guidance. Fix directions in the item: a distinct error class carrying
actionable guidance, and including the matched pattern descriptions in the
agent-visible message. Acceptance criteria explicitly forbid changing
rejection strictness.
