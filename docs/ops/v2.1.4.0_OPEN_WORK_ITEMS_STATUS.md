## #290 (OPEN) — Injection-rejected memory writes surface a retry-inviting error class instead of rephrase guidance

**Author:** applejack | **Created:** 2026-10-02 01:51Z (since first repass) | **Labels:** 2.1.5.0, enhancement, low

From sweetiebot's WI#280 study (ledger LOW). When the injection gate rejects
a memory write, the agent-visible error reads like an authorization failure,
inviting a retry of the same content instead of a rephrase. Post-!1332 the
most common trigger (quoted describing-context in `daily/*.md`) no longer
fires, so the exposure is the unquoted rejection path and non-daily
prompt-visible files. Verified in this tree: `injection_rejected_error`
(`ic/src/workspace/mod.rs:152`) builds `WorkspaceError::InjectionRejected`
with the matched descriptions joined into `reason`, used by both the strict
path (`:182`) and the daily-log path (`:329`); the descriptions reach the
daemon log via `tracing::warn!` but the agent gets no rephrase/quote
guidance. Fix directions in the item: a distinct error class carrying
actionable guidance, and including the matched pattern descriptions in the
agent-visible message. Acceptance criteria explicitly forbid changing
rejection strictness.

## #289 (OPEN) — Safety sanitizer: detection is stricter than the crate's own neutralization (mid-sentence matches vs line-start-only defusing)

**Author:** applejack | **Created:** 2026-10-02 01:51Z (since first repass) | **Labels:** 2.1.5.0, enhancement, low

From sweetiebot's WI#280 study (ledger LOW-MED). Detection matches bare
case-insensitive substrings anywhere in the text, while the crate's escape
path defuses only line-start role labels — so content the crate itself would
neutralize at render is hard-rejected at write. Affects all prompt-visible
files, not just daily logs. Verified in this tree: `detect`
(`ic/crates/lunarwing_safety/src/sanitizer.rs:254`) is the context-blind
scanner; `escape_content` (`:259`) rewrites only lines whose trimmed
lowercased start matches a role marker (`:271-288`). The item asks for a
recorded decision: align detection with neutralization context-sensitivity,
or document strict-at-ingress/lenient-at-render as deliberate.

## #288 (OPEN) — Workspace daily-log gate: unquoted poisoned file blocks all appends for the day (no tool-level self-heal)

**Author:** applejack | **Created:** 2026-10-02 01:51Z (since first repass) | **Labels:** 2.1.5.0, bug, medium

From sweetiebot's WI#280 study (ledger MED). A daily-log file containing
unquoted High-severity content blocks every subsequent append for the day,
because appends rescan the full combined candidate and `daily_log` has no
overwrite mode — recovery needs operator/disk intervention. Verified in this
tree: `Workspace::append()` rescans the combined candidate before commit
(`ic/src/workspace/mod.rs:1169`) and again after commit with a compensating
restore (`:1180`), and the severity floor is hardcoded
(`reject_if_injected` at `:168` → `reject_if_injected_at(…, Severity::High)`).
Post-!1332, *quoted* poison demotes and no longer sticks; the
gap is unquoted poison plus the missing recovery path. Ranked fix shapes in
the item: quarantine-on-append-failure (rename the poisoned file aside,
start fresh, no silent data loss), an operator-gated repair verb, or minimum
rejection detail naming file and line.
