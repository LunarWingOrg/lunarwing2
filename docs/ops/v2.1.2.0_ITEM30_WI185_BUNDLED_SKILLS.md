# Item 30 — WI#185: Remove unnecessary default skills for freshly provisioned tenants

Date: 2026-09-21
Branch: `aj/kimi-30-20260921-1801`
Work item: https://git.lunarwing.org/lunarwing/lunarwing2/-/work_items/185

## Problem

Every fresh tenant received ten bundled skills, compiled into the daemon binary by
`ic/build.rs` (`embed_skills` collects `ic/skills/*/SKILL.md` into
`embedded_skills.json`) and loaded at startup as `Trusted`-level discovery sources
(`ic/src/skills/bundled.rs`, `ic/src/skills/registry.rs::load_bundled_skills`).
Three of those ten were LunarWing **contributor** workflows, not tenant capabilities:

| Skill | Why it is not a tenant default |
| --- | --- |
| `web-ui-test` | WI#185's named example — "Web UI Testing with Claude for Chrome". Manual web-UI walkthroughs driven through the proprietary Claude for Chrome browser extension. Useless to a tenant (they are not testing LunarWing's UI) and depends on proprietary tooling. |
| `local-test` | Build/run/test LunarWing from source locally via `Dockerfile.test` with "Chrome MCP" browser automation. A contributor/dev-VM workflow; also references retired NearAI provider endpoints. |
| `review-checklist` | LunarWing's own pre-merge PR review checklist ("issues caught by automated code reviewers (Copilot, Gemini) on LunarWing PRs"). Repo-internal QA process, meaningless outside this repository. |

This also conflicted with the project philosophy (`MANIFESTO.md`): the project does
not support proprietary channels/tooling (Claude for Chrome, Google/Chrome MCP,
Copilot/Gemini reviewers) as product defaults — such tooling is fine for individual
contributors on their own machines but must not be pushed to every provisioned
tenant as a bundled default.

## Change

- Deleted `ic/skills/web-ui-test/`, `ic/skills/local-test/`, `ic/skills/review-checklist/`
  (commit `a1c0ab458`). Bundled embedding is directory-driven, so removal from
  `ic/skills/` removes them from the compiled catalog and from every fresh tenant.
- Added regression coverage in `ic/src/skills/bundled.rs`:
  `bundled_catalog_is_exactly_the_product_skill_set` pins the bundled catalog to the
  seven product skills and fails if a removed dev skill reappears (WI#185 guard) or
  if the catalog changes without the expected list being updated.

The remaining seven bundled skills are product capabilities and stay:
`cavepony`, `delegation`, `lunarwing-workflow-orchestrator`, `multica-poll`,
`plan-mode`, `routine-advisor`, `study-notes`.

Operator opt-in is unaffected: users who want the removed content back can place
any skill in `~/.lunarwing/skills/` (highest priority) or their workspace
`skills/` dir — bundled skills were always the lowest-priority source and any
user skill with the same name overrides the bundled one.

## Scope notes / decisions

- No code, registry, or channel versions were touched — the bundled skill catalog
  is not a versioned registry package (unlike WASM channels/tools); it is embedded
  at compile time. No lockfile or `check-version-bumps.sh` impact.
- No existing skill names or activation patterns overlap with the removed skills
  (`web-ui-test`/`local-test`/`review-checklist` had no references outside their
  own SKILL.md files; verified by repo-wide sweep).
- Other bundled skills were evaluated and kept deliberately:
  - `review-checklist` was the only borderline keep-candidate (generic review
    hygiene), but its content is LunarWing-PR-specific (Copilot/Gemini reviewer
    patterns, this repo's trait/decorator chain rules) — not a tenant default.
  - `lunarwing-workflow-orchestrator` references GitHub but operates through
    LunarWing's own native routines/tools on the tenant's own configured GitHub
    tool; it is a product capability (autonomous project orchestration), not
    dev tooling. Kept.
- `ic/Dockerfile.test` (referenced only by the deleted `local-test` skill body)
  stays: it is a standalone contributor image documented in its own header, not
  part of the bundled skill catalog.
- The stale NearAI mention the audit doc flagged at
  `docs/ops/NEAR_REMOVAL_COMPLETION_AUDIT.md` inside `ic/skills/local-test/SKILL.md`
  is resolved by this removal (the file no longer exists); the audit doc is a
  historical record and was not edited.
