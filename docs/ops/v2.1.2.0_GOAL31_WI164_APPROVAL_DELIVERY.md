## Changes

- **Lost approval/auth prompts:** authenticated `/api/chat/pending-gates` snapshot
  from the durable store. Browser recovery on initial connection, reconnect,
  history/thread reload, and stream-gap history reconciliation. Cached gates
  survive DOM replacement; live events supersede stale snapshots; resolved IDs
  are tombstoned. Failed recovery retries, and expired/resolved prompts are
  removed on reconciliation.
- **Auto-approve drift:** Engine V2 reads resolved agent configuration. The old
  `AUTO_APPROVE_TOOLS` key is an alias with canonical-key preference within each
  precedence layer. Legacy/unknown agent-key warnings log names only. Explicit
  approval, disabled tools, shared-channel restrictions, and supervision retain
  their checks.
- **Cold conversation lookup:** read and create use persisted surfaces; a cache
  miss never creates during lookup. Lock ordering and post-I/O rechecks prevent
  deadlock, duplicate creation, and overwriting newer in-memory state. Auth
  matching has the same exact-thread fallback as other gate controls, scoped to
  the same user and permitted channel.
- **610-second result loss:** owned late watcher, event forwarding, bounded
  second wait/stop grace, and normal channel reply routing. On-time and late
  outcomes share `bridge/router/outcome.rs`; terminal transport shares
  `agent/response_delivery.rs`, including outbound hooks and coalescing.
- **Review !1012:** every completed response passes response hooks, including
  authentication-marker text. Valid transformed auth requests create durable,
  resolvable gates. Rejection/error suppresses assistant history and delivery.
- **Disk-only zombie gates:** startup restore removes expired file entries.
- **Review !1030:** recovered auth prompts preserve request/thread identity for
  token submission and cancellation, including token-only prompts. The backend
  rejects stale, mismatched, expired, partial, and foreign-user identities.
  Cancellation finalizes the exact waiting thread and removes the durable gate;
  the browser tombstones only after confirmation. Token configuration queues a
  secret-wrapped control that revalidates the exact gate before resuming, without
  entering chat parsing/history. Same-extension sibling prompts retain their
  identities across thread switches and delayed responses.
- **Proactive gateway messages:** the effect adapter supplies execution-local
  thread routing to the `message` tool; gateway identity overrides shared
  defaults.

## Compatibility and operational limits

No schema or dependency change. Existing pending-gate files remain readable;
rollback cannot recover already-pruned expired entries. The legacy env alias
means a previously ignored `AUTO_APPROVE_TOOLS=true` now takes effect for
`UnlessAutoApproved` tools: migrate to the canonical name and set it explicitly
to `false` if that behavior is unwanted.

The late watcher is bounded and in-process. Daemon restart/shutdown does not
provide exactly-once durable outbound delivery. The recovery endpoint is
available to external SSE/WebSocket clients, but bundled browser behavior is
what these tests exercise. Desktop/Android application rendering and live
tenant traffic require their own validation; the voice checks described in the
issue were already reported passing and are outside the changed paths.
