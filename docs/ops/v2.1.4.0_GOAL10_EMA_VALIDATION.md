# Goal 10 / WI191 — tool-runtime EMA integration

Branch: `cmc/g10/v2.1.4.0`. Implementation and local validation: 2026-09-30.

## Delivered scope

- Registry-owned, user/tool-scoped, bounded in-memory calibration feeds the
  existing estimator from real tool completions. Shared execution, local job
  workers and lightweight routines all use the same execution-only timer.
- Five-sample warmup, optional actual cost, unadjusted-baseline ratios, frozen
  forecast errors, numeric guards and bounded outlier influence. Failures,
  timeouts, cancellation and approval/auth waits do not train completed runtime.
- Opt-in runtime hints on both legacy approval creation paths and the v2 gate
  insertion path; frozen descriptions survive their existing live/history/
  recovery routes. Missing redacted parameter snapshots now render `null`,
  rather than exposing execution parameters, on both v1 and v2 display paths.

The initial WI191 tool/pending-gate acceptance slice is implemented. Later
LLM timing, whole-job/mission ETA, gate-wait analytics and durable aggregate
caches remain in the [integration plan](../plans/WI191_PERFORMANCE_EMA_INTEGRATION.md).
Detailed contract: [runtime estimation](../../ic/src/estimation/README.md).

## Rollout and compatibility

`LUNARWING_TOOL_ESTIMATES` is read once per registry at startup:

| Value | Behavior |
|---|---|
| Unset / `observe` | Record only; no new approval hints |
| `1` | Record and show hints after warmup |
| `0` | Disable recording and new hints |

Restart resets learned models. Persisted pending gates retain their original
description, including any hint. No database migration or new wire fields are
required. The legacy numeric `Estimator::record_actuals` API remains available;
live instrumentation uses its new optional-measurement API. Costs stay unknown
in production until a tool supplies both a cost baseline and an actual charge.
