## Conclusion

**Eight vulnerability advisories and one informational unmaintained
advisory are accepted and shipped; none of them is unaccounted for, and no
committed lockfile contains any *other* crate with an active applicable
security advisory.** This is a risk-acceptance statement, not a clean bill:

- **5 of the 8 vulnerability advisories compile into default builds**:
  `rustls-webpki 0.102.8` (RUSTSEC-2026-0049/0098/0099/0104, two of them
  certificate name-constraint bypasses) and `h2 0.3.27`
  (RUSTSEC-2026-0258), both via the libsql 0.6.0 legacy chain. The webpki
  copy validates X.509 for libSQL remote-replica TLS connections to
  third-party database hosts. Postgres-only builds do not contain either
  crate.
- **3 of the 8 compile into every feature set**: `rsa 0.10.0-rc.18`
  (RUSTSEC-2023-0071, exercised only by ssh-tool RSA auth behind a
  LunarWing-enabled russh feature) and `failure 0.1.8`
  (RUSTSEC-2019-0036/2020-0036, vendored libsignal-protocol wrapper).
- The informational acceptance is `rental 0.5.6` (RUSTSEC-2021-0134,
  unmaintained, **no vulnerability**), visible only in the widened
  `--workspace --all-features` graph.
- Every accepted entry carries an exposure statement and a clearing work
  item (table below), and the patched copies of advisory-pinned crates are
  protected against silent downgrade by `[bans]` version floors.

All 26 checkable manifest roots pass `cargo deny check advisories`
(cargo-deny 0.20.2, `--workspace --all-features`, shared `ic/deny.toml`
policy) against the advisory DB above, and the one manifest-less reviewed
lock (`pebble4lunarwing/upstream/Cargo.lock`) remains gated by
`pebble4lunarwing/scripts/verify_upstream_lock.py`.

Upstream re-verification (crates.io sparse index, 2026-10-03): libsql
0.9.30 (max stable) and 0.10.0-pre.4 (newest) still request
`hyper-rustls ^0.25` / `hyper ^0.14` / `tonic ^0.11`, so a libsql bump
today keeps the chain (#1–#5). rsa 0.10.0-rc.18 is still the newest
published release and russh 0.63.3 (latest) still pins `rsa =0.10.0-rc.18`
(#6). failure 0.1.8 is the final release (#7–#8).

**Downgrade protection (new, review A3):** the advisory ignores above are
keyed by ID, which cannot fire if a future lockfile regresses the
*patched* copy. `[bans]` now denies `h2 >=0.4.0, <0.4.19` and
`rustls-webpki >=0.103.0, <0.103.15`, flooring the patched lines while
leaving the accepted legacy copies (0.3.27 / 0.102.8) outside the denied
ranges. Every committed lock currently sits at h2 0.4.19 /
rustls-webpki 0.103.15 on the patched lines.

## Gates (all committed, all wired into CI full-validation)

1. **cargo-deny** (`.gitlab/scripts/cargo-deny-check.sh`) — ic workspace,
   `--workspace --all-features` (the ~900-crate graph CI compiles, not the
   ~889-crate root-package default query that missed openssl, rental,
   json5, and `lunarwing_health_metrics`; review A4), unvendored context
   so `yanked = "deny"` is verifiably enforced, `index-failure` diagnostics
   fatal, advisory-db commit printed.
2. **satellite-advisory-sweep** (`.gitlab/scripts/check-satellite-advisories.sh`,
   new; review A5) — discovers every tracked `Cargo.lock` via
   `git ls-files` and runs the same pinned cargo-deny with the shared
   `ic/deny.toml` policy over all 26 manifest roots. New satellite roots
   are swept automatically; `validate_config.py` pins the wiring.
3. **lockfile-only-advisory-guard** (`.gitlab/scripts/check-lockfile-only-advisories.sh`,
   reworked; review A2) — covers pins cargo-deny cannot see. Queries now
   run `--workspace --all-features --target all` (the vendored
   libsignal-protocol path deps are automatic workspace members, so their
   dev-deps DO resolve) with per-entry modes, and an entry whose crate
   leaves the lockfile fails as stale instead of passing vacuously:

   | Crate | Mode | Advisories | Truth on this tree |
   |---|---|---|---|
   | `pyo3 0.28.3` | `absent` | RUSTSEC-2026-0176 (OOB read), RUSTSEC-2026-0177 (`PyCFunction::new_closure` missing `Sync`) | Not in any resolve graph (uncompiled `jiter/python` feature pin, WI#255) |
   | `atty 0.2.14` | `no-dev` | RUSTSEC-2021-0145 (Windows-only unaligned read, no patched release) | **Is** compiled for the vendored libsignal-protocol's own tests via dev-dep `env_logger 0.6.2`; never in a non-dev (shipped) build graph |
