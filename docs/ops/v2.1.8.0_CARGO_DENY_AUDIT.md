# Crate Security Audit — v2.1.8.0

**Date:** 2026-10-31 (item 2, branch `aj/kimi-2-20261031-0600`, Rarity).

**Scope:** pre-release checklist item #2 — "Crate security audit for v2.1.8.0,
run on the tree after item 1's crate sweep has merged". Item 1 (the v2.1.7 →
v2.1.8 crate sweep, branch `rarity/kimi-1-20261031-0000`) is merged at
`7ba88e9c1`, so this audit runs on the **post-sweep** tree as the item

resolved and scanned separately). Also re-run: the CI advisory gates, the
default-graph and lockfile-only guards, a full-graph unmaintained pass, an
independent yanked-crate pass, and a re-verification of every accepted
advisory's upstream blocker.

## Findings

### No fixable finding on any audited root

Every live advisory on the 27 roots is either (a) one of the 13 documented
`ic/deny.toml` acceptances with no patched release on the pinned line, or
(b) the two lockfile-only `pyo3` pins the guard exists for (below). A direct
advisory-db-vs-lock classification over all 27 roots found **25 distinct
(crate, version, advisory) findings**: 10 with a patched release named,
12 unmaintained (informational), 2 unsound, and 1 (`rsa`) with `patched = []`.

The 10 "patched exists" rows are **not** actionable on this tree: each is the
legacy `libsql 0.6.0` chain or the `russh → rsa` pin, and the patched range
lives on a release line the pinned parent cannot reach (see the acceptance
table). The only root that ever carried a live, fixable finding was the pebble
worker lock, and the v2.1.7.0 cycle already remediated it — verified clean
below.

### 1. The shipped pebble worker lock is clean on the post-sweep tree

`pebble4lunarwing/upstream/Cargo.lock` is manifest-less, so
`.gitlab/scripts/check-satellite-advisories.sh` skips it by design and its
state is owned by the SHA256/override-delta gate. Resolved against a pristine
upstream checkout at the pinned `PEBBLE_REF`
(`2d0f3786cbebb705cbd4f6212b0aaf47d8d8590b`) with the committed override, the
resulting graph reports **advisories ok, bans ok** — no quinn-proto, tokio or
clipboard-win finding (all fixed in the v2.1.7.0 cycle), and pulldown-cmark is
already at the patched **0.13.5** (RUSTSEC-2026-0414, fixed during v2.1.7.0).
The 13 `warning[advisory-not-detected]` lines on that graph are expected:
cargo-deny's ID-keyed ignore list reports one warning per `ic/deny.toml`
acceptance the pebble graph does not contain. `cargo-audit` over the same lock
reports **0 vulnerabilities**. `pebble/Cargo.lock` (the pinned snapshot behind
the same `PEBBLE_REF` contract) is likewise clean and also at
pulldown-cmark 0.13.5.

## Yanked-crate pass

`yanked = "deny"` is active and was verifiably enforced: the main gate and
every satellite root ran from the repo root with the real crates.io index and
**zero `index-failure` diagnostics**. An independent pass queried the sparse
crates.io index for the exact locked version of **4135 registry package pins
across all 27 locks** and found **no yanked pin anywhere** — the single yanked
pin of the v2.1.7.0 cycle (pebble's clipboard-win 5.4.1) is already at 5.4.3.

## Unmaintained-crate enumeration (informational, not vulnerabilities)

Temporary policy copy with `unmaintained = "all"` over the ic
`--workspace --all-features` graph (the committed policy stays `"workspace"`):
**9 entries** — `atomic-polyfill`, `atty`, `bincode`, `fxhash`,
`rustls-pemfile`, `ttf-parser`, `zbus_names 3.0.0` (RUSTSEC-2026-0371),
`zvariant 4.2.0` (RUSTSEC-2026-0370), `zvariant_derive 4.2.0`
(RUSTSEC-2026-0372). The three zbus entries arrive via `zbus` /
`secret-service` (secret storage) and are folded into zbus 6.0.0 upstream;
migrating zbus is a separate dependency task. All are maintenance notices,
not security holes. `yaml-rust 0.4.5` and `bincode 1.3.3` additionally appear
only in the pebble locks via upstream's syntect, unchanged. Of the remaining
informational advisories reachable in locks, `dirs`, `ring`, `humantime` and
`json5` are **withdrawn** advisories and are not findings.
