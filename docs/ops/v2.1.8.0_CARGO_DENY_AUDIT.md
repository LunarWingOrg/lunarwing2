# Crate Security Audit — v2.1.8.0

**Date:** 2026-10-31 (item 2, branch `aj/kimi-2-20261031-1800`).

**Scope:** pre-release checklist item #2 — "Crate security audit for v2.1.8.0,
run on the tree after item 1's crate sweep has merged". Item 1 (the v2.1.7 →
v2.1.8 crate sweep) is merged, so this audit runs on the **post-sweep** tree
as the item requires (daemon version 2.1.8, every owned package bumped, every
lockfile updated). All **27 tracked non-vendor Cargo.lock roots** were scanned

re-verification of every accepted advisory's upstream blocker.

reviewer fable): TA-1 (Low, the RSA acceptance rationale still named
"russh 0.64.1" and was last re-verified 2026-10-10), TA-2 (Info, two wording

## Findings

### No fixable finding on any audited root

Every live advisory on the 27 roots is either (a) one of the 13 documented
`ic/deny.toml` acceptances with no patched release on the pinned line, or
(b) the two lockfile-only `pyo3` pins the guard exists for (below). A direct
advisory-db-vs-lock classification over all 27 roots found **25 distinct
(crate, version, advisory) findings**: 10 with a patched release named,
12 unmaintained (informational), 2 unsound, and 1 (`rsa`) with `patched = []`.

The 10 "patched exists" rows are **not** actionable on this tree. They break
down as **8 from the libsql 0.6.0 legacy chain** (5 rustls-webpki 0.102.8, 2
rustls 0.22.4, 1 h2 0.3.27) and **2 pyo3 0.28.3 lockfile-only pins**
(RUSTSEC-2026-0176/0177); `rsa` is the separate `patched = []` row. Each
patched range lives on a release line the pinned parent cannot reach (see the
acceptance table). The only root that ever carried a live, fixable finding was
the pebble worker lock, and the v2.1.7.0 cycle already remediated it —
verified clean below.

### 1. The shipped pebble worker lock is clean on the post-sweep tree

`pebble4lunarwing/upstream/Cargo.lock` is manifest-less, so
`.gitlab/scripts/check-satellite-advisories.sh` skips it by design and its
state is owned by the SHA256/override-delta gate. Its pinned digest
(`sha256sum` = **`19f4e96c…`**) matches `PEBBLE_LOCK_SHA256` in
`pebble4lunarwing/Dockerfile`. `cargo-audit` over this lock and over
`pebble/Cargo.lock` (the pinned snapshot behind the same `PEBBLE_REF`
contract) both report **0 vulnerabilities**, with only 2 unmaintained
notices each (bincode 1.3.3, yaml-rust 0.4.5 via upstream's syntect).
Pulldown-cmark is already at the patched **0.13.5** (RUSTSEC-2026-0414, fixed
during v2.1.7.0). The quinn-proto, tokio and clipboard-win findings from the
v2.1.7.0 cycle are all resolved.
