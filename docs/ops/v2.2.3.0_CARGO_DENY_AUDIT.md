The index and vendored manifest agree that `postcard 1.2.0` still defaults
to `heapless ^0.7.0`. Its optional `heapless-v0_9` feature can now select
`heapless ^0.9.4`. A clearing change would turn off the legacy default path
for every parent and use the fixed optional line only if needed. Enabling the
new feature alone leaves the old pin. WI #928 tracked the clearing option and
the historical rationale that still cited `postcard 1.1.3`, the old
compatibility claim, and modern `h2 0.4.20`; WI #934 landed the clearing.

The `[bans]` rules check **direct parents**. Below 0.9.4, only `postcard`
may depend directly on `heapless`. Below 2.0.0, the allowed direct parents
of `postcard` are `monty`, `wasmtime`, `wasmtime-environ`, and
`wasmtime-internal-cache` (WI #788). A new direct parent outside either list
fails the ban. A new dependency path through an allowed parent can still
reach the old pin, and these rules do not constrain feature changes to
allowed edges. The `atty` and legacy `hyper-rustls` wrapper rules have the
same direct-parent semantics.
