## What landed (per finding)

### Finding 1 (MED) — headless stall from yolo + dangerous-command guard → FIXED

- `kimicode4lunarwing/config/config.toml` — `default_permission_mode` `yolo`→`auto` (upstream
  0.40.0 yolo holds dangerous-class commands for approval; auto approves
  everything, the correct headless mode) and new `[permission]
  dangerous_command_guard = false`. Correction (WI#206 verification,
  2026-09-21): upstream's guard policy service bypasses evaluation under
  `auto` mode, so the mode switch alone already neutralizes the guard — the
  `dangerous_command_guard = false` setting and entrypoint exports are
  belt-and-suspenders for mode drift or a custom `KIMI_CONFIG_SOURCE` that
  drops the baked `[permission]` table, not an independent second fix. The
  earlier "prompts in ALL permission modes" phrasing here was imprecise
  (it prompts in Manual/YOLO; it cannot prompt under auto).
- `kimicode4lunarwing/entrypoint.sh` — both `cli` and `websocket` modes export
  `KIMI_CODE_PERMISSION_MODE_REMINDER=0` (0.43.0 fixed-mode reminder is prompt
  noise) and `KIMI_CODE_DANGEROUS_COMMAND_GUARD=false` (belt-and-suspenders when
  a custom `KIMI_CONFIG_SOURCE` drops the baked `[permission]` table). Both use
  `${VAR:-default}` so operators can still override via the tenant env file.

Consequence removed: a dangerous-class shell command no longer reaches an
approval prompt headless `-p` cannot answer — the class of `timed_out` stall
WI#194 described.

### Finding 2 (MED) — mock-only test surface, real CLI flag contract unpinned → FIXED

- New `scripts/kimi_cli_contract_test.ts` executes the REAL installed kimi
  binary and asserts both halves of the headless flag contract:
  1. `-p <prompt> --output-format stream-json` is ACCEPTED (must exit 0 against
     an unreachable provider, never usage-rejected 64/2),
  2. `--yolo` is REJECTED alongside `-p` with stderr naming the flag — the exact
     reason `kimi_task_executor.ts` relies on config-only auto-approval.
  Both tests self-skip when no kimi binary resolves (host dev machines).
- `kimicode4lunarwing/Dockerfile` — the in-image gate now runs `npm test`
  (full mock suite + contract lane) then a second `npm ci --prefix
  /opt/kimi-cli` at the locked `@moonshot-ai/kimi-code@0.43.1` and re-runs JUST
  the contract tests against that binary's `bin/` dir, so the contract is
  asserted on the exact CLI version the image ships (reproducible pin — no
  `@latest`).
- Host verification: suite went 42→44 tests, contract lane executed against the
  host's kimi 0.42.0 (both assertions pass).

### Finding 3 (LOW-MED) — role-only stream parsing silently drops unknown roles → FIXED

- `scripts/kimi_task_executor.ts` — `processStreamLine` now `console.warn`s per

- New mock behavior `unknown-role` in the executor suite: asserts the warn fires
