## #81 (OPEN) — `context.rs` role-token regression test allegedly tautological

<https://git.lunarwing.org/lunarwing/lunarwing2/-/work_items/81> · reporter: sunburst ·
filed 2026-08-27 against `fb841a64`

**Finding: the filed tautology claim is contradicted by the cited source.**

- At both cited commit `fb841a64` and this audited HEAD (the file is unchanged),
  `formatted_docs_neutralize_role_tokens_in_all_untrusted_fields` constructs a
  `MemoryDoc` whose title and content contain raw `<|im_start|>`, `<|im_end|>`, and
  `<|endoftext|>` openers, calls the real `format_docs_as_context`, then asserts that the
  result contains no `<|` and does contain each exact zero-width-space replacement
  (`ic/crates/lunarwing_engine/src/executor/context.rs:184-202`). If the neutralizer were
  removed or became an identity function, assertions at lines 196-198 would fail. The
  final equality at lines 199-202 checks idempotence; it is not the test's only assertion.
- The production formatter applies neutralization to the complete joined section, covering
  current and future metadata (`context.rs:72-103`). `build_step_context` appends exactly
  that returned string to the system prompt (`context.rs:51-66`). Python parity separately
  asserts forged role tokens are absent (`executor/orchestrator.rs:2813-2824`).
- The exact Rust regression passed during this audit:
  `executor::context::tests::formatted_docs_neutralize_role_tokens_in_all_untrusted_fields`.

**Actual narrow gap:**

- There is no single test that passes a forged `MemoryDoc` through `build_step_context`
  and inspects the final assembled system message. The existing suite tests benign
  assembly (`context_injects_docs_after_system_prompt`) and malicious formatter output
  separately. Adding the requested integrated assertion would improve defense-in-depth,
  but the claim that the neutralizer or read-path transformation is untested is false and
  no production correctness fix is indicated.
