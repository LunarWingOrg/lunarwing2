## Findings fixed this cycle

### 1. The shipped pebble worker lock still carried five live quinn-proto advisories, one unsound tokio pin, and one yanked crate

`pebble4lunarwing/upstream/Cargo.lock` is manifest-less, so
`.gitlab/scripts/check-satellite-advisories.sh` skips it by design and its
state is owned by the SHA256/override-delta gate. Unlike the other roots it
had therefore not picked up the 2026-10-23 remediations, and a plain
lockfile-text scan (cargo-audit, advisory-db `21d909e4`) showed:

| Package | Before | Finding | Disposition |
|---|---|---|---|
| `quinn-proto` | 0.11.16 | RUSTSEC-2026-0338 (remote panic on zero-length STREAM frames), 0339 (unbounded pending connection-ID retirements), 0340 (peer `min_ack_delay` panic), 0341 (stream-reassembly cap bypass), 0342 (zero-length DATAGRAM frames bypass the receive-buffer limit); patched `>=0.11.18` for 0338/0340 and `>=0.11.17` for 0339/0341/0342 | **0.11.19** |
| `quinn` | 0.11.11 | same patch line as every other audited root | **0.11.12** |
| `quinn-udp` | 0.5.15 | companion to the quinn bump; only its version/checksum lines change (NX-1) | **0.5.16** |
| `tokio` | 1.52.3 | RUSTSEC-2026-0386, unsound safe `AsyncFd` constructors (`unsound = "all"` in `ic/deny.toml`) | **1.53.3** |
| `clipboard-win` | 5.4.1 | yanked (`yanked = "deny"`) | **5.4.3** |

Reachability, stated precisely rather than overclaimed: quinn is locked
through reqwest's weak `quinn?/ring` edge, `http3` is off by default, and no
pebble build can compile it without an upstream manifest change (which would
also change `PEBBLE_REF` and this lock), so it is **lockfile-only for every
pebble build** — the same class the lockfile-only advisory guard exists for.
Enabling `http3` would make all five advisories live; the override now pins
the patched levels, so that flip is safe.

The refresh was produced with `cargo update -p <crate> --precise <version>`
against a pristine upstream checkout at the pinned `PEBBLE_REF`
(`2d0f3786cbebb705cbd4f6212b0aaf47d8d8590b`), not by hand-editing records.
Run-214 NX-1 then reverted the four incidental `windows-sys` edge
re-pointings introduced by `cargo update`, so the final lock changes **only
the version and checksum lines of those five packages** (20 changed lines);
no dependency edge is re-pointed, `windows-sys 0.61.2` stays locked, and no
package is added or removed.

Guard changes in the same commit: `PEBBLE_LOCK_SHA256` re-pinned
(`f68c9e35…` → **`24fc1c22…`**), the reviewed allowlist in
`pebble4lunarwing/scripts/verify_upstream_lock.py` gains only the new package
names with per-entry rationale (NX-1 keeps `errno`, `rustix` and
`winapi-util` out of it), and its summary line no longer claims a
four-crate-only delta. `docs/ops/WORKER-CONTAINERS.md` records the new levels
and the override's audit path.

### 2. A stale acceptance hid behind `advisory-not-detected`

`ic/deny.toml` accepted **RUSTSEC-2026-0381** on `webpki-roots 0.26.11`.
Advisory-db `21d909e4` marks that exact version
**`unaffected = ["= 0.26.11"]`**: the 0.26.11 compatibility shim carries no
independent trust store and re-exports the roots of its separately resolved
1.x dependency (locked at the patched **1.0.10**, and its own record names
`webpki-roots 1.0.10`). The ignore therefore only produced
`warning[advisory-not-detected]` on every gate run. It is **removed**, with a
comment recording why; the accepted-ID total drops 14 → **13**. A downgrade
of the 1.x parent is still a hard failure through the same advisory, and the
default-graph guard is unchanged.

## Yanked-crate pass

`yanked = "deny"` is active and was verifiably enforced: the main gate and
every satellite root ran from the repo root with the real crates.io index and
**zero `index-failure` diagnostics**. The independent cargo-audit pass over
all 27 lockfiles confirms **no yanked registry-locked version anywhere**
after the clipboard-win fix (the only yanked pin found was the pebble
override's clipboard-win 5.4.1, plus upstream's chacha20 0.10.1 already
retired to 0.10.2 in a previous cycle).

## Out of scope / remaining confirmations

- Routine semver updates and the libSQL TLS migration, dropping `russh/rsa`,
  porting the vendored Signal wrapper off `failure`/`rental`/`atty`, and the
  zbus 6 migration are separate work items, not item-3 remediations.
- **Deployed pebble worker images are not patched by this commit alone.** The
  image build is the protected `worker-pebble-candidate` /
  `worker-pebble-scan` gate: rebuild the image so the refreshed override is
  compiled in, verify the candidate and its trivy scan before promotion, and
  confirm the branch pipeline is green on GitLab. Those are the CI/deploy
  steps this dev VM cannot certify.
- The three pre-existing `TrivyRetryWrapperBehaviorTests` timeouts and the
  container-runtime smoke error are environment artifacts reproduced on the
  untouched base; they are not introduced or worsened here.
