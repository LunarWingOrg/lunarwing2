    - DONE 2026-10-03 (`testing1/l00p/v2.1.5.0`, item 20, WI#276): source study at HEAD (KB `mission-thread-death-retry-gap-wi270`, re-traced in `runtime/mission.rs`/`runtime/manager.rs`) confirmed the silent loss but **corrected the WI's mechanism**. The outcome watcher sat in `select!` on `tm.join_thread(thread_id)`, which on its first poll *removes* the `RunningThread` (signal sender, run token, JoinHandle) from the running set. On shutdown its `stop_thread_system` therefore hit `ThreadNotFound` (discarded), the dropped join detached the run, the run kept going and was dropped mid-await at runtime teardown, and the cancel arm returned without recording anything. The row was left `Running` (cron/manual fires → `Failed("engine restart…")` after restart, no marker) or terminal with its outcome never processed: no approach record, no retry marker, dedup key kept. The same root cause made `stop_insight_workers`, `is_running` and injected messages miss every watched mission thread.
    - Fix: new `ThreadManager::wait_thread_or_stop` (`ic/crates/lunarwing_engine/src/runtime/manager.rs`) waits by polling `is_running` and joins only once the run has finished, so the thread stays registered and stoppable — the router's turn-wait pattern ("never remove a still-running handle just to join it"). If the shutdown token fires first it requests the stop and gives the run a grace to settle, returning `Ok(None)` without joining if it doesn't. The watcher (`spawn_mission_outcome_watcher`) uses it with `SHUTDOWN_STOP_GRACE` = 3 s (inside `MissionManager::shutdown`'s 5 s wait) and processes the **real** outcome through the existing `process_mission_outcome_and_notify`. For `Stopped` that records `INTERRUPTED: signal-stopped mid-run`, releases the trigger dedup key, and persists the `mission_retry` marker on the now-terminal thread (no lost-update race: the watcher writes only after the run's own final save). The in-process retry timer is skipped during shutdown, and the existing post-restart sweep (`recover_pending_mission_retries`) re-arms it from the marker. A run that finished inside the window gets its real outcome recorded, so it is not double-fired. An unsettled run is left untouched (warned), since writing then would race its live final save — that case, and hard kills, belong to restart recovery (WI#301, goals item 5, deliberately not touched here).
