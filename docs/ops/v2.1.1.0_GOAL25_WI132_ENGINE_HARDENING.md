## 2. What was implemented

### Item 2 — memory index desync (outbox + repair sweep)

- **Schema:** `ic/migrations/V27__memory_index_outbox.sql` (Postgres, refinery) and libSQL incremental V27 (`ic/src/db/libsql_migrations.rs`): `memory_documents.indexed_at TIMESTAMPTZ/TEXT` — NULL = content changed, chunk projection stale. Backfill stamps pre-existing rows as indexed (`indexed_at = updated_at`) so an upgrade never triggers a surprise mass re-embed; partial index `idx_memory_documents_stale_index` on the NULL set.
- **Producers closed:**
  - `append_document` (both backends) sets `indexed_at = NULL` in the SAME statement that commits content.
  - content-only `update_document` (both backends) sets `indexed_at = NULL` (closes the append_memory two-phase window).
  - `update_document_and_replace_chunks` and `replace_chunks` stamp `indexed_at` inside the same transaction that rebuilds chunks.
- **Delete path (items 2/3):** `delete_document_by_path` now deletes chunks + doc row in ONE transaction on both Postgres (`ic/src/workspace/repository.rs`) and libSQL (`ic/src/db/libsql/workspace.rs`). No more chunkless-content or orphan-chunk half-states.
- **New trait method:** `WorkspaceStore::list_stale_index_documents` — non-empty content, `indexed_at IS NULL`, excluding `engine/.runtime/` (intentionally zero-chunk; must never enter search).
- **Repair sweep:** `Workspace::repair_stale_index(limit)` re-chunks stranded docs (bounded, newest-first, per-doc failures logged not propagated). Wired at boot (`ic/src/app.rs`, before `backfill_embeddings` so healed chunks embed in the same pass) and periodically on the heartbeat hygiene task (`ic/src/agent/heartbeat.rs`).
- **Append error contract:** append/append_memory/append_to_layer no longer return Err after content is durable — a failed reindex is logged and healed by the sweep, so LLM tool retries can no longer duplicate committed entries.
- **Split-pattern compensation:** when a prompt-visible append passes the pre-commit candidate scan but the post-commit full-content scan rejects (injection split across appends), the pre-append content is restored atomically (`update_document_and_replace_chunks`) and the error returned — rejected content no longer persists. Known tradeoff: a concurrent append inside the compensation window is lost; prompt-visible files are low-frequency and injection removal wins.
- **Detector SQL for operators** (read-side audit; run against a quiesced DB):
  ```sql
  SELECT id, path, updated_at, LENGTH(content) AS content_bytes
  FROM memory_documents d
  WHERE content <> '' AND indexed_at IS NULL
    AND NOT (path = 'engine/.runtime' OR path LIKE 'engine/.runtime/%');
  ```

### Item 1 — authenticity boundary (minimal-diff seams from the v4/v5 map)

- **`__retrieve_docs__` choke point:** returned docs are neutralized (`neutralize_role_token_openers`) and carry `"provenance": "untrusted_memory_retrieval"` so mission code cannot relay poison into provider messages without a label (`orchestrator.rs`).
- **System-role backstop at both LLM adapters:** `convert_messages` (rig adapter, all completion paths) and `ChatCompletionMessage::from` (LunarWing Cloud chat) neutralize System-role content — idempotent on already-neutralized engine prompts, closes the `__llm_complete__` explicit-System seam. User/Assistant intentionally untouched (user content is the user's own).
- **Skill trust minting closed:** `__save_memory_doc__` forces `trust: "trusted"`, `source: "extracted"` and strips `pending_patch`/`pending_prune` from Skill docs — the explicit-mint hole, the omission hole (`source` serde-defaults to `Authored`), and the propose-then-approve bypass are all closed in one place. Non-skill docs' metadata is inert (SkillTracker only parses Skill docs).
- **Compaction laundering:** the summary is prefixed `[Compaction summary — LLM-generated, replaces earlier conversation history]` and neutralized; `Provenance::LlmGenerated` was already set on the message.
- **Daily-log scan gap:** `daily/*.md` joins the write-time injection scan set (`is_daily_log_file` in `is_system_prompt_file`) — the one file class the LLM itself appends to is now sanitized before it can persist into every system prompt.
- **Dead neutralizer removed:** `executor/context.rs` (`build_step_context`/`format_docs_as_context`, zero production callers) deleted with its tests; the live seams are now the covered ones.

### Deliberately NOT changed (recorded residuals)

- **Preamble/orchestrator self-modification:** already fail-closed behind `ORCHESTRATOR_SELF_MODIFY` (default off) with defense-in-depth in `HybridStore::save_memory_doc`. The residual (no content-trust check when an operator enables it) is documented, not re-engineered.
- **Ghost rows from live-daemon purges (bridge in-process map):** purge protocol must stop the daemon first — operational procedure (see §4); the delete-path atomicity fix removes the DB-side half-state producer.
- **Retrieval fallback amplifier:** recency fallback retained (weak context beats false "not found"), but everything it injects is now neutralized + labeled at the `__retrieve_docs__` boundary. A full DocOrigin attestation schema remains a design item if wanted.
- **`sanitize_tool_messages` still Tool-only:** System coverage moved to the adapter layer (both providers); widening User/Assistant neutralization would alter user-visible text and is out of scope.

## 4. Operational notes

- **Purge protocol (item 3, live systems):** stop the daemon BEFORE SQL purges — `HybridStore` re-persists in-memory docs on subsequent saves (ghost rows). This is the operational half; the DB half-state producer is fixed in code here.
- **Missions restart protocol (item 6):** with items 1+2 landed (this branch), missions may be re-enabled per the WI stance; scope-limited walks + exclusion list remain operator policy.
- **Upgrade behavior:** V27 backfills `indexed_at` — no mass re-embed on first boot after upgrade. Docs stranded BEFORE the upgrade stay stranded (invisible to search, intact on read) until their next write; run the §2 detector SQL if pre-upgrade desync is suspected.
- **Rollback:** revert the branch; V27 columns are additive (old code ignores `indexed_at`; refinery/libSQL migration tables record it harmlessly).

## 6. MR !899 review follow-ups (landed on `rarity/kimi-25-20260911-1800`)

cmc's own MR review ("approve with one recommended pre-merge fix", 2026-09-11 13:09) listed one MEDIUM and four low findings. All addressed:

- **MEDIUM — delete-by-path lookup escaped the transaction (both backends).** `delete_document_by_path` resolved the document on a separate pool connection before opening the tx; a concurrent delete made both DELETEs no-ops while the call still returned `Ok(())`. The id is now resolved **inside** the transaction (`ic/src/workspace/repository.rs`, `ic/src/db/libsql/workspace.rs`), and a missing row returns `DocumentNotFound` — pinned by the new test `delete_missing_document_returns_not_found`.
- **libSQL malformed-UUID silent nil-mapping.** `list_stale_index_documents` no longer maps unparseable ids to `Uuid::nil` (which would make the sweep fail per-pass forever); it skips + warns so the rest of the sweep keeps healing.
- **libSQL V27 idempotency.** `(27, "memory_documents", "indexed_at")` added to `IDEMPOTENT_ADD_COLUMN_MIGRATIONS` for parity with V15/V20/V25.
- **Repair-without-embedding-provider concern — verified sound, no change.** `prepare_chunks` chunks and inserts NULL embeddings when no provider is configured, which is the same shape the existing `write()` path produces; the boot sweep therefore needs no provider gate. (Reviewed `ic/src/workspace/mod.rs::prepare_chunks` / `replace_chunks` on both backends.)
- **Misleading lifecycle-fields comment.** Reworded: `__save_memory_doc__` *strips* `pending_patch`/`pending_prune` (SkillTracker's propose-then-approve staging fields) rather than passing them through as the old comment implied.

## 7. WI#135 follow-up (landed on `rarity/kimi-29-20260912-2215`)

WI#135 (cross-thread mission-context leakage) is the **input side** of the same
mechanism family this doc fixes on the persistence side: one mission's
`mission.json` goal text was tenant-wide searchable via `memory_search`. Fixed
by item 29 of the 2.1.1.0 goals:

- **Write-time exclusion:** `is_mission_path` in `ic/src/workspace/document.rs`
  excludes the whole mission-directory subtree
  (`engine/projects/*/missions/*/**`) plus the project-level
  `engine/projects/*/missions.json` manifest from the search index
  (`is_search_indexable_path`); documents stay stored and readable (mission
  hydration reads documents, not chunks). Subtree-wide exclusion (not just the
  exact `mission.json` basename) closes the adjacent-artifact leak
  (`mission.json.bak`, `other.json`, extra segments, the `missions.json`
  manifest) flagged as MEDIUM on WI#136.
- **Legacy-chunk purge:** `Workspace::purge_mission_index_chunks` deletes
  pre-fix chunks via `purge_chunks_for_path_pattern` with the subtree pattern
  `engine/projects/%/missions/%` and the manifest pattern
  `engine/projects/%/missions.json` (both backends), wired at
  boot BEFORE the embedding backfill and on the heartbeat hygiene pass.
  Idempotent; no schema change.
- **Provenance belt-and-suspenders:** `build_memory_search_output` labels
  engine-internal results (`engine/**`) with `"provenance":
  "engine_internal"`, mirroring the `untrusted_memory_retrieval` seam above.
- **FTS nonce-tokenizer secondary finding** (WI#135) explicitly NOT coupled to
  this fix — filed as a separate follow-up (tokenizer flattening of
  suffix-shared nonces).
