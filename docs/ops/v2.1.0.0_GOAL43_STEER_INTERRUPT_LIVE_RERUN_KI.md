## Issues found along the way

1. **WeeChat WASM channel traps on every poll (fresh tenant).** ~30s cadence
   `Polling callback failed channel=weechat … WASM execution trapped`
   (opaque wasmtime backtrace). Discriminated live: started ~1 poll after a
   tenant restart; persists with the IRC network disconnected AND with the
   server entry deleted (pristine zero-IRC-buffer state); derpy/spitfire/
   dwarfstar show zero occurrences. Only capabilities delta vs a healthy
   tenant: `dm_policy: "open"` (test edit) + per-tenant ports. Prime
   suspect: the open-policy/empty-allowlist path in the weechat channel.
   Repro: fresh tenant → set dm_policy=open → restart. Needs its own work
   item. W1/W2 therefore skipped on sun's instruction (rarity's heron pass
   may cover them on her setup).
2. **XMPP DM replies never delivered to the peer (fresh tenant, throwaway
   prosody).** Inbound proven end-to-end (prosody → bridge → daemon: "Prepared
   polled message for agent queue channel=xmpp"); the agent completes the
   turn and the bridge emits the reply attempt (log: "XMPP OMEMO lookup
   failed, falling back to plaintext DM … ItemNotFound"), but the plaintext
   stanza never arrives at the connected peer. Sun's guidance: OMEMO normally
   needs 1–2 plaintext exchanges before devices settle and it is
   client-dependent — a fresh bare-bones peer may not satisfy the bootstrap;
   treat as environment/bootstrap-shaped, not a confirmed code defect.
   Getting here surfaced real wiring knowledge worth keeping: the bridge
   honors `SSL_CERT_FILE` for its TLS trust (openssl-probe; pointing it at
   the server CA fixed the handshake — a leaf cert in the anchor position
   yields `CaUsedAsEndEntity`, and prosody's plaintext path requires
   `c2s_require_encryption=false`/`allow_unencrypted_plain_auth=true` on this
   image).
3. **`function_name::lunarwing` upstream flakiness tonight.** Three gateway
   turns ended `Failed` with empty responses on that function; a trivial
   completion took ~10s. Switched the tenant to `function_name::FrontierCODE`
   — all subsequent turns clean and fast. Environmental, but note empty
   `Failed` turns can be mistaken for control-flow bugs.
4. **v1 history shows a gate-paused turn as `Failed` during the pause
   window** (flips to `Completed` after the expiry-resume wrap-up). Minor
   display nit worth a tracker line — during the 2-minute pause the turn
   labeled itself Failed, which is misleading to anyone watching history.
