## Preventing another green-MR/red-integration cycle

Previously, `.full-validation-context` included an MR targeting the default
branch, but not one targeting `aragents/kimil00p/*`. Both failed jobs were
therefore absent from the preceding dependency-sweep MR pipeline. Integration
MRs now run those gates and the complete backend/security validation matrix.
An unmerged scratch branch can opt in with `LUNARWING_CI_FULL_VALIDATION=1`.
Worker publication stays protected and push-only; validation caches stay
pull-only on these branches.

The earlier !1267 pipeline
[#4684](https://git.lunarwing.org/lunarwing/lunarwing2/-/pipelines/4684) is green
at `9fad7de50`, but has none of `cavepony-wasm`, `architecture-boundaries`,
`rust-check-libsql`, `rust-clippy-all`, or `cargo-deny`. Its reduced job graph
does not satisfy goal 1's full-validation exit criterion.

`ci-config` now checks all five Cavepony version surfaces before compiling.
Its regression suite rejects stale/missing/corrupt version metadata, an
unlocked Cavepony build, or removal of the integration-MR rule. It also checks
that full-validation opt-in cannot widen worker publication rules.

## Version-policy follow-up

The initial local configuration checks proved version agreement but did not
run the base-aware version-policy gate. The exact failing CI command was
reproduced against !1267's base `9fad7de507b7ad4c1fa315fe19cf04a66ec006eb`:
`Registry version: 0.4.3 -> 0.4.3`. Metadata and lockfile corrections count as
tool source changes, so matching that already-shipped registry version is
insufficient. The policy remains unchanged; the corrected release is `0.4.4`.

The shell regression harness now exercises the production CI wrapper with
an explicit MR base and a different push-before SHA. It rejects metadata-only
alignment without a new registry release, then accepts an incremented release.
To verify the proposed fix using the same base as job #85616, run from the
repository root:

```bash
CI_MERGE_REQUEST_TARGET_BRANCH_NAME=aragents/kimil00p/v2.1.4.0 \
CI_MERGE_REQUEST_DIFF_BASE_SHA=9fad7de507b7ad4c1fa315fe19cf04a66ec006eb \
CI_MERGE_REQUEST_LABELS='' bash .gitlab/scripts/version-policy.sh
```
