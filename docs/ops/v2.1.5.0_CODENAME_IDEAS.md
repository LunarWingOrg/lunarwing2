# LunarWing v2.1.5.0 Codename Ideas

LunarWing v2.1.5.0 is the cycle of return and tempering. The version sweep
moved every LunarWing-owned package from `2.1.4` to `2.1.5`, `ic/vendor/` was
regenerated, and the external-crate security audit was re-run as a fully
re-attempted MR (item 3) with all six adversarial findings (A1–A6) addressed:
the lockfile-only advisory guard lost its false premise, the audit graph
widened to `--workspace --all-features` (~900 crates), and a new satellite
sweep covers all 26 manifest roots. The engine's resilience spine was rebuilt
across a dozen work items: context-overflow recovery now climbs the full
shrink ladder at default config instead of stalling on a per-streak clamp
(WI#298); global boot recovery re-adopts orphan-project threads, preserves
Waiting approvals, and records restart-lost mission fires without replaying
side effects (WI#301); malformed orchestrator outcomes fail loud and count
toward rollback (WI#302); the pending-gates file gained atomic writes,
0o600 modes, and a quarantine path so a corrupt state file cannot brick the
execution gate (WI#299); `rlm_query` children no longer leak provider
diagnostics to the model (WI#296); mission capabilities answer `tool_info`
truthfully about leases (WI#295); and the lightweight-routine tool budget was
un-clamped from its hidden `.min(5)` cage into one honest hard limit of 10
(WI#291).

The cycle's defining shape, though, is rebirth through review. Nearly every
feature item this release began life as a REJECTED or SALVAGED merge request —
items 3, 5, 6, 9, 11, and 14 through 22 each name the previous MR whose
adversarial findings had to be heeded before the work could land. Nothing was
abandoned: each attempt returned folded over its reviewer's findings until it
merged clean. Even the build infrastructure learned to heal itself —
`refresh-vendor.sh` now checks the WI#292 rig-core marker before and after
vendoring and restores the committed patched tree from git when a vendor run
fails or is interrupted (WI#294).

Taken together, this is a release about **rebirth: refused work returned
stronger, crashed state recovered honestly, and steel folded until the
impurities came out**. The goals header already carries the pre-selected
codename **Bungei Fukkō (文芸復興, "The Renaissance")**; this document is the
candidate slate and assessment behind that selection. All candidates follow
LunarWing's Japanese word/name convention and repeat no previous release
codename (`Kawarimi`, `Takamaru`, `Tatara`, `Kiyome`, `Togishi`, `Dōkutsu`,
`Sashiko`, `Odoshi`, `Kagi`, `Kairo`, `Mihari`, `Sekisho`, `Inazuma`,
`Ma-ai`, `Zanshin`, `Yoroi`, `Ō-Yoroi`, `Kabuto`).

## Candidates

### 1. Bungei Fukkō (文芸復興)

**English context:** "The Renaissance"; the revival of arts and letters
after a dormant period.

The name the goals header already carries, and the most honest one for this
cycle. A renaissance is not invention from nothing — it is the return of
dormant work with new rigor. That is exactly what happened to items 3, 5, 6,
9, 11, and 14–22: previously rejected or salvaged MRs were re-attempted
against their adversarial findings and merged, turning the review trail of
the last cycle into the feature list of this one. The word also fits the
engine's recovery spine — threads, approvals, and mission fires that survive
restarts instead of dying silently. Fukkō breaks slightly from the
single-word tradition (like `Kawarimi` or `Zanshin`), but the goals file
already committed to it, and the meaning earns the exception.

### 2. Tamahagane (玉鋼)

**English context:** "Jewel steel"; the folded steel of a traditional blade,
purified by repeated hammering.

Tamahagane names the *process* this release embodies. Each fold of the steel
removes an impurity; each adversarial review round removed a flaw — the gate
persistence MR returned with quarantine, 0o600 modes, and atomicity proofs
(WI#299); the cargo-deny audit returned with six findings closed (item 3);
the rig-core vendor guard returned with its EXIT trap and marker checks
(WI#294). The result is harder and cleaner than any single pour. It also
continues the sword-craft thread `Togishi` (v2.0.1.0, the polisher) opened,
one step earlier in the forge.

### 3. Yomigaeri (蘇り)

**English context:** Resurrection; coming back to life.

Yomigaeri is the plainest name for the recovery spine. Boot recovery brings
orphan-project threads back into the global listings (WI#301); context
overflow revives turns that used to die at the clamp (WI#298); stopped
threads persist honest terminal states instead of vanishing (WI#302); and
corrupt gate state revives as an empty-but-usable file rather than bricking
the gate (WI#299). Distinct from v2.0.5.0 candidate `Kaifuku` (回復, recovery
of a condition): yomigaeri names the return of a thing that had died.

### 4. Tanren (鍛錬)

**English context:** Tempering through repeated practice and forging;
discipline earned by doing the rep again.

Tanren captures the review culture that defined the cycle: every feature
item was done, rejected, and done again — sometimes three times — until the
findings were exhausted. It also fits the engine work, where recovery is not
a one-shot retry but a ladder (0.60x then 0.35x) climbed under discipline
(WI#298). Where `Zanshin` (v2.1.1.0) named sustained attention, tanren names
the repetition that turns attention into muscle.

### 5. Hagane (鋼)

**English context:** Steel; iron refined of its impurities.

The shorter, harder sibling of candidate 2. The cargo-deny re-audit refined
the dependency graph (five advisories compiling into default builds, three
into every feature set — all named, none unaccounted); the vendor
regeneration refined the pinned third-party tree; and the adversarial
reviews refined every feature MR. Hagane is what the forge leaves behind.
Simple, strong, and easy to say in release notes.

### 6. Akebono (曙)

**English context:** Daybreak; the first light before dawn.

Akebono frames the cycle as the turn from the dark — the dark being dropped
missions, bricked gates, leaked diagnostics, and false-passing audits, all
retired this release. It is the gentler alternative to `Inazuma` (v2.0.9.0,
lightning): not a strike, but the light returning after a long night of
rejected MRs.

### 7. Shūren (修練)

**English context:** Ascetic training; cultivation through repeated
exercise.

Shūren names what the re-attempt pattern actually was: the same exercise
performed under correction until it was right. The WI#299 gate work, the
WI#294 vendor guard, and the item-3 audit each passed through multiple
rounds of adversarial findings (A1–A6, S12, N1–N5, R8–R10) before merging.
The word carries the humility of the loop — the work is never finished, only
further trained.

### 8. Noroshi (狼煙)

**English context:** A signal fire; the smoke beacon that announces an event
to distant watchers.

Noroshi fits the notification and observability thread: restart-lost mission
fires are now recorded and notified instead of silently dropped (WI#301);
the lightweight-routine fix restored the digest notification that used to
spend its rounds and never send (WI#291); and `refresh-vendor.sh` now warns
by naming each marker file that lacks the tripwire. The release makes the
system better at announcing what happened to it.

### 9. Menkyo (免許)

**English context:** A license or certification; the formal grant of
competence after examination.

Menkyo suits the verdict work: the cargo-deny audit certifies exactly which
advisories ship and why, with the guard failing a stale entry rather than
carrying it forward; the mission `tool_info` answer certifies whether a
thread actually holds the lease it asks about (WI#295); and the gate
persistence work certifies state on disk the way a license certifies its
holder — corrupt credentials are quarantined, not honored (WI#299). Adjacent
to the v2.1.4.0 candidates `Kiwame` and `Mekiki` but focused on the grant,
not the eye.

### 10. Fukugen (復元)

**English context:** Restoration to original form; reconstruction of what
was lost.

Fukugen names the state-restoration work precisely: orphan-project threads
restored to global listings, Waiting approvals restored across restarts,
corrupt gate files restored to a usable empty state, and the committed
rig-core patch tree restored from git after a failed vendor run (WI#294).
Where candidate 3 names the return of life, fukugen names the return of
form.

## Seed Shortlist (considered, not shortlisted)

The earlier seed notes in this file proposed the Japanese terms for
"enlightenment" and "renaissance" as the naming space. For the record:

- **Keimō (啓蒙)** — "the Enlightenment"; the standard term (啓蒙時代,
  啓蒙主義). Passed over: it connotes dispelling others' ignorance, where
  this cycle was about correcting our own work through review.
- **Bunmei kaika (文明開化)** — "civilization and enlightenment"; the
  Meiji-era modernization catchphrase. Passed over: too broad and political
  for a maintenance-and-recovery release.
- **Satori (悟り)** — Zen awakening. Passed over: the religious connotation
  overshoots a dependency-and-recovery cycle.
- **Runesansu (ルネサンス)** — the katakana loanword for Renaissance. Passed
  over: the kanji form 文芸復興 carries the same meaning in the established
  convention.

## Top Picks

### 1. Bungei Fukkō

Best overall — and already the name on the goals header. A renaissance is
the return of dormant work with new rigor, and that is the literal shape of
this cycle: a feature list built mostly of previously rejected MRs, reborn
through adversarial review until they merged.

```markdown
## Release Codename:  文芸復興
## English Context:   Bungei Fukkō — the Renaissance; dormant work returned with new rigor
```

### 2. Tamahagane

Best process metaphor. Steel folded until the impurities come out is exactly
what adversarial review did to every feature MR this cycle, and it continues
the sword-craft lineage `Togishi` began without repeating the armor family
of the last three releases.

```markdown
## Release Codename:  玉鋼
## English Context:   Tamahagane — jewel steel, purified by repeated folding
```

### 3. Yomigaeri

Best recovery metaphor. Threads, approvals, mission fires, and gate state all
come back from the dead in this release, and the word translates the release
to anyone in one line.

```markdown
## Release Codename:  蘇り
## English Context:   Yomigaeri — resurrection; what died returns to life
```

## Recommendation

Keep **Bungei Fukkō (文芸復興)** for LunarWing v2.1.5.0. The goals header
already pre-selected it, and the cycle justifies the choice: this is the
release where refused work came back — items re-attempted against their
adversarial findings, crashed state recovered honestly, and audits re-run
until their premises were true. If a shorter single-word name is ever
preferred for packaging or display, **Tamahagane (玉鋼)** is the strongest
fallback from this slate; **Yomigaeri (蘇り)** is the best plain-word
alternative.
