## #105 (OPEN) — long-running tool calls and mid-turn control

<https://git.lunarwing.org/lunarwing/lunarwing2/-/work_items/105>

This report separates two controls that the tracker description conflates.

**`/interrupt` is addressed:**

- The Engine V2 run token now wraps CodeAct execution, direct tool calls, and
  parallel tool batches with `CancellationToken::run_until_cancelled`
  (`ic/crates/lunarwing_engine/src/executor/orchestrator.rs:476-551`).
- Cancelling drops the active host-call future and returns a normal stopped
  outcome; CodeAct child futures use abort-on-drop ownership.
- `cancelled_code_step_aborts_in_flight_tool` exercises a hanging tool and
  requires prompt stopped completion with no fabricated action event
  (`ic/crates/lunarwing_engine/src/executor/orchestrator.rs:4135-4198`). It
  passed during this audit.

**`/steer` is not a tool-cancellation command:**

- The documented contract is injection at the next model-call boundary, after
  the current step/tool result. It deliberately does not abort the current tool
  (`docs/architecture/ENGINE-V2.md:474-481`).
- Therefore, the report's observation that a single 120-second tool completed
  before a valid `/steer` affected the next step can be expected behavior. A
  `//steer` message is not the `/steer` command, and ordinary prose remains
  ordinary queued input.
- If #105 requires `/steer` itself to preempt a tool, that feature is not
  implemented and would be a semantic change, not a regression fix. If it asks
  only that a valid steer survive the tool and reach the next model call, the
  current queue/injection fixes address it.

**Verdict:** interrupt-side defect fixed and regression-tested; steer-side
expectation needs reporter clarification plus the planned fresh long-tool live
retest in item 43.
