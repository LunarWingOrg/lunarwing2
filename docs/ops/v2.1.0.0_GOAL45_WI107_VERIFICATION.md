## WI#107 hypothesis re-check

- **H1, normal and streamed response event missing:** not reproduced. Terminal
  text still passes through the channel response path after streaming, where
  emotes are parsed and attached.
- **H1, interrupt residual:** the stopped engine task still maps to an empty
  response sentinel so it does not create a duplicate assistant row. However,
  the user-facing `/interrupt` control returns `"Interrupted."` from
  `ic/src/bridge/router.rs:2815-2832`; the priority-control path sends that
  non-empty result through normal outbound delivery at
  `ic/src/agent/agent_loop.rs:1350-1364`. The resulting emote-less gateway
  response moves the widget from working to idle. The earlier item-33 warning
  that a normal `/interrupt` necessarily leaves it working for 30 seconds does
  not describe the current complete control flow.
- **H2, parser misses the herd's dialect:** fixed by `b5d678db9` and covered by
  the passing real-dialect tests.
- **H3, italic prose can false-positive:** unchanged documented trade-off. Only
  bounded single-asterisk spans containing a configured keyword classify.
- **H4, WebSocket drops `emotes`:** disproven in source and now explicitly
  regression-tested with non-empty emotes.

## Live public-surface observation

`lunarwing-mt-admin.sh list-tenants` found six registered OpenRC tenants. Five
had a responding gateway. Of those, antelope and kestrel had the mascot opt-in:

- `/api/health` returned `{"status":"healthy","channel":"gateway"}`;
- the page injected `/mascot.js`;
- the served script SHA-256 matched the workspace script
  (`daa72b0db5f4ae90ff73cbd31921a6d7144c387d5e85e4e5fcec1faa8e756795`);
- all eight `/mascot/lunar_*.gif` routes returned HTTP 200.

which is correct for disabled tenants. No gateway token or tenant secret was
read. Because the public API exposes no source commit and authenticated chat was
not used, these observations validate the deployed static surface, not a
source-matched live parser-to-SSE turn.
