## Scope

Test every external worker (pebble, opencode, opencode2, kimi) on a fresh
multi-tenant tenant, with worker images built **with toolchains**
(Rust/Go/C++/Python/Node in-image). Drive long-running, complex jobs through
the tenant daemon's `job_create` builtin tool that exercise the workers' own
tools: Python, Rust, and C compiles/runs inside the worker containers.

Host: Gentoo dev VM, systemd (user-manager tenant units), podman rootless
per-tenant stores, 12 cores / 23 GiB RAM.

## Setup record

- Tenant: `extworktest`, created 2026-10-05 via
  `mt-admin add-tenant extworktest --docker-group --no-ssh --no-weechat-bootstrap --no-health --with-pebble --with-opencode --with-kimi --with-opencode2 --llm-api-key <reused from tenant antelope> --llm-base-url http://cotterhomelab3.netbird.selfhosted:3000/openai/v1`
- Tenant checkout: this branch (mt-admin clones the current checkout's branch).
- Pebble NanoGPT key: reused from tenant antelope's `pebble.env` via
  `mt-admin configure-pebble extworktest --nanogpt-api-key <key>` (never printed).
- Build: `mt-admin build-tenant extworktest --with-pebble --with-opencode --with-kimi --with-opencode2 --with-toolchains`

## Test design

Per worker, driven through the tenant's web gateway chat
(`POST /api/chat/send` on a fresh thread) instructing the tenant agent to call
`job_create` with `mode: <worker>`, `wait: false`:

1. **gauntlet** (primary): write+compile+run a C program (gcc -O2, 300x300
   matrix multiply), create+build+run a Rust cargo project (naive fib(35)),
   write+run a Python 3 script that parses both outputs into report.json,
   optional Go run, then write SUMMARY.md and list the workspace.
2. **smoke** (fallback/diagnostic): write smoke.txt and cat it back.

Jobs polled via `GET /api/jobs` / `/api/jobs/{id}`; artifacts collected via
`/api/jobs/{id}/events` and `/api/jobs/{id}/files/{list,read}`. Tool approvals
answered with `always` via `POST /api/chat/approval`.

## Findings and failure analysis

<!-- FINDINGS -->

Interim (pre-retry) findings:

1. **Engine V2 gate path (not v1 approvals) governs `create_job` from gateway
   chat.** Gateway threads run through the Engine V2 Monty CodeAct
   orchestrator; `create_job` is a Privileged action and parks in the engine
   gate store (`GET /api/chat/pending-gates`), not the v1
   `pending_approval` history field. Approval via
   `POST /api/chat/approval {action: "always"}` resumes the thread.
2. **Gate-resume flakiness (observation, not fixed here):** 2 of 4
   first-round dispatches (pebble, opencode threads) resumed after approval
   into a model text FINAL without re-issuing the gated `create_job` call;
   their gates remained listed in `pending-gates` after the threads went
   terminal ("stale approval: thread not in AwaitingApproval state" on
   re-delivery). kimi's identical approval resumed into a real `create_job`.
   A follow-up engine look at gate-resume determinism is warranted.
3. **kimi baked config uses a NetBird MagicDNS name**
   (`cotterhomelab3.netbird.selfhosted`) which does not resolve inside
   rootless podman containers (container DNS: 169.254.1.1/9.9.9.9). The task
   burned 9 provider retries over 140s and failed with
   `provider.connection_error`. Fix applied to the tenant:
   `configure-kimi --base-url http://100.88.232.146:3000/openai/v1 --model tensorzero::function_name::lunarwing`
   (numeric NetBird IP routes fine in-container; verified 400/OK from both
   host and container).
4. **opencode v1 + opencode2 baked default baseURL is
   `http://192.168.1.157:3000/openai/v1/`** — an RFC1918 address that is not
   routable from this host (a cloud VPS with no 192.168.x interface; route
   goes to the public gateway). opencode2's first gauntlet succeeded against
   it at 15:23Z, but the address has been unreachable from host and container
   since ~15:31Z (flaky upstream path). Both workers were given the numeric
   NetBird IP override and rerun for a reproducible result.
5. **pebble (NanoGPT direct) passed cleanly**, including a smoke job
   (13s) and the full gauntlet. Minor image warts visible to the agent:
   `cargo`/`go` were not on the worker shell's default PATH; pebble recovered
   for Rust by locating the rustup toolchain under
   `/usr/local/rustup/toolchains/1.96.1-.../bin` itself and recorded the
   missing `go` in SUMMARY.md.
6. **opencode2 executor SDK drift (non-fatal):**
   `sdk.session.message.list is not a function` when fetching assistant text
   post-task; the task itself completed and reported success.
